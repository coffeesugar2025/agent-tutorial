# 第 0 章 总纲与决策边界

> 这一章决定后面 8 章要不要用、用多少。多数项目失败在这里，不在实现细节。

## 0.1 概念谱系与边界
- Prompt → Chain → RAG → Tool-Using → Agent → Multi-Agent 的演进逻辑
- **自主性（autonomy）≠ 复杂度（complexity）**：多步不一定多 Agent
- Agent 的严格定义：模型自主决定「下一步做什么」并「调用外部能力」的闭环系统
- 与以下形态的区别：Workflow、Chatbot、Copilot、RPA、规则引擎
- 常见误判：把固定流程包装成 Agent（成本更高、更不可控）

## 0.2 任务可 Agent 化的判据
- 任务是否**可分解**为可执行子步骤
- 是否存在**可验证的反馈信号**（测试、校验、人工确认）
- **错误成本**：错了能不能撤销？代价多大？
- **调用频率**与**延迟容忍度**
- **数据可得性**：所需上下文能否在运行时获取
- **长尾程度**：规则能不能穷举？能穷举就该用规则
- 反向指标：强确定性、强审计、极低延迟、极低成本 → 不该上 Agent

## 0.3 自主性分级
- L0 纯生成 / L1 单轮工具调用 / L2 多步自主循环 / L3 长时任务 + 人工审批 / L4 多 Agent 自治
- 每一级的**责任归属**与**故障半径**

## 0.4 产品形态与人机分工
- Copilot（人主导）/ Chat（人提问）/ Autonomous（机器主导）/ Embedded（隐形）
- 决策权分配：谁提议、谁批准、谁执行、谁兜底
- 交互形态对技术选型的约束（同步 vs 异步、流式 vs 批处理、可否打断）

## 0.5 ROI 与成本模型
- **有效成本 = 单任务推理成本 / 成功率 + 人工兜底成本**
- 成功率的边际收益 vs 成本的边际投入
- 成本预算的分配：模型调用 / 检索 / 工具 / 人工审核
- 什么阶段该"先跑通再优化"，什么阶段必须"先算账"

## 0.6 架构选型决策树
- 单次调用 → 链式 Prompt → Workflow/DAG → 单 Agent → Supervisor 多 Agent
- 每一层的引入条件与退出条件
- **默认倾向 workflow，而非 multi-agent**：可预测、可调试、成本可控

## 0.7 常见认知误区（自查）
- Agent 越多越强 / 步数越多越准
- 长 Prompt 能解决一切（实际是上下文污染源）
- RAG 能消除幻觉（实际会引入新的幻觉）
- 上了 Agent 就能替代人工流程
- 一次评测通过 = 生产可用

# 第 1 章 模型与推理层

## 1.1 模型谱系与能力边界
- 闭源：OpenAI、Claude、Gemini、DeepSeek、Qwen、GLM、文心、通义、Kimi
- 开源：Llama、Qwen、DeepSeek、Mistral、GLM、Phi
- 分类维度：通用 / 推理 / 代码 / 多模态 / 小模型（端侧）
- **能力–成本–延迟三角**：任何选型都是三者取舍
- 各模型在**函数调用、并行工具、长上下文、结构化输出**上的差异
- 模型版本漂移：供应商静默升级带来的行为回归

## 1.2 Tokenizer 与上下文窗口
- BPE 原理、中英文 token 效率差异（直接影响成本与切片）
- 计费口径：输入 / 输出 / 缓存命中 / 思考 token
- **标称上下文 vs 有效上下文**：标称 200K 不等于能用满
- 长上下文的"中间失忆"（lost in the middle）与 needle-in-a-haystack 测试
- 上下文长度对延迟与成本的非线性影响

## 1.3 推理模型与 Test-time Compute
- 推理模型（reasoning model）与普通模型的行为差异
- **thinking budget / reasoning effort**：什么时候开、开多少
- 成本换算：思考 token 的钱是否换来成功率提升（要做 A/B，别假设）
- 推理内容是否应回传进上下文（多数场景不必）
- `【进阶】` 测试时扩展（采样多数投票、自我一致性、best-of-n）

## 1.4 Prompt Engineering
- 结构范式：角色 / 任务 / 约束 / 示例 / 输出格式 / 分隔符
- **指令优先级**与冲突处理（系统 > 开发者 > 用户 > 数据）
- Few-shot：示例选择、数量、顺序敏感性、负面示例
- 思维链（CoT）的适用与失效场景
- 负面指令（"不要…"）的脆弱性，改用正向约束
- Prompt 即代码：版本化、diff、回归测试

## 1.5 结构化输出
- JSON Mode / JSON Schema / 严格模式的能力差异
- **约束解码（constrained decoding）**：文法（grammar）、FSM、JSON schema 强约束
- Schema 设计：枚举优先、必填明确、避免深层嵌套
- 解析失败的处理：重试、修复（repair）、降级到自由文本 + 抽取
- 结构化输出与流式的冲突及解法

## 1.6 采样参数与不确定性
- temperature / top_p / top_k / presence / frequency / seed
- 可复现性：即使 temperature=0 也非严格确定（批处理、硬件、MoE 路由）
- 多次采样与投票：何时值得
- 置信度信号：logprob、自一致性、模型自评

## 1.7 模型路由与级联 `【进阶】`
- 难度路由：小模型先试，置信度不足再升级
- 成本路由 / 任务类型路由（代码→代码模型，长文→长上下文模型）
- 级联（cascade）的判定点设计与误判成本
- 路由器的训练方式：分类器 / LLM 判别 / 规则
- 多供应商抽象层与 fallback 链

## 1.8 成本与延迟优化
- **Prompt Caching / Prefix Caching**：稳定前缀的布局技巧，命中率决定省钱幅度
- 批处理 API（离线任务降本）
- 流式输出（改善体感延迟，不降低总时长）
- 输出长度控制（max_tokens、格式约束）
- 投机解码、量化推理对延迟的影响
- 延迟分解：排队 + 首 token + 生成 + 工具 + 检索，定位真正的瓶颈

## 1.9 多模态能力 `【进阶】`
- 图像 / 音频 / 视频输入的能力边界与 token 成本
- 文档视觉理解 vs OCR + 文本（版面复杂时前者更优）
- 多模态输出的适用场景

# 第 2 章 单 Agent 核心

## 2.1 Agent Loop
- 基本循环：观察 → 思考 → 行动 → 观察
- 消息历史的数据结构（system / user / assistant / tool call / tool result）
- 单轮工具调用 vs 多步自主循环
- ReAct 的原始形态与工程变体（隐式推理、结构化 scratchpad）
- 循环的每一圈在消耗什么：token、时间、金钱、用户耐心
- **循环不变式**：每轮必须产生信息增量，否则应终止

## 2.2 规划（Planning）
- 任务分解与子目标生成
- **todo list 作为外部状态**：为什么写进上下文比"想在心里"可靠
- Plan-and-Solve、Plan-then-Execute 的取舍（计划刚性 vs 灵活性）
- ReAct（边想边做）vs 先规划后执行：适用场景对比
- `【进阶】` Tree of Thoughts、LATS、树搜索与回溯
- `【进阶】` Reflexion / 自我批评 / 失败后重规划
- **重规划触发条件**：连续失败、环境反馈矛盾、预算过半未完成
- 规划的常见病：过度规划、计划漂移、计划与执行脱节

## 2.3 工具设计学（最被低估的一章）
- 工具命名：动词开头、语义唯一、避免近义工具
- 工具描述：**何时该用 / 何时不该用**、输入语义、返回语义、边界
- 参数 Schema：枚举、必填、默认值、单位、格式示例
- 返回值设计：结构化数据 + 人类可读摘要 + 稳定错误码
- **返回值 token 预算**：工具一次返回 50K token 是 Agent 崩溃的常见原因
- 工具粒度：过细导致步数爆炸，过粗导致一次做错
- 工具数量与选择准确率：超过阈值应做**工具检索 / 动态加载**
- 危险工具分级：只读 / 可写 / 不可逆，分级授权与二次确认
- 幂等性标注：让模型知道重复调用是否安全
- 错误消息要**可操作**（告诉模型怎么改），而非堆栈

## 2.4 工具调用机制
- 并行调用与依赖编排
- 结果截断与摘要策略
- 单工具超时、整体超时
- 部分失败的处理（继续 / 重试 / 换路 / 上报）
- 调用预算（次数上限、金额上限）
- 工具返回不可信：把工具输出当**数据**而非**指令**（安全伏笔）

## 2.5 上下文工程（Context Engineering）
- 上下文预算分配：指令 / 历史 / 检索 / 工具结果 / 预留输出
- **KV-cache 友好布局**：稳定内容放前，易变内容放后
- 压缩策略：滚动摘要、分层摘要、结构化抽取、丢弃低价值轮次
- 裁剪策略：保留最近 N 轮 + 关键事实表 + 当前目标
- 子 Agent 上下文隔离（把脏活放进独立上下文，只回传结论）
- **文件系统作为外部记忆**（把大块中间产物落盘，只留路径）
- Scratchpad / 便签 / 任务清单的写入时机
- 动态工具注入：按需加载工具定义，降低基础 prompt 体积
- 常见病：上下文污染、指令淹没、前后矛盾、无关检索塞满窗口

## 2.6 记忆体系
- 分层：工作记忆（当前轮）/ 会话记忆 / 长期记忆 / 用户记忆
- 会话记忆实现：全量窗口、滑动窗口、摘要、向量检索回溯
- 长期记忆类型：语义（事实）/ 情节（经历）/ 程序性（做法）
- **写入策略**：什么值得记？何时写？（即时 / 会话结束 / 异步抽取）
- 记忆的检索与注入时机
- 遗忘与衰减、冲突消解（新旧事实矛盾怎么办）
- 记忆的隐私边界与用户可见可删
- `【进阶】` 记忆压缩、记忆图谱、跨会话用户画像

## 2.7 终止条件与预算控制
- 完成判定：显式 finish 工具 vs 隐式文本判定
- 硬约束：最大步数、最大 token、最大时长、最大花费
- **无进展检测**：连续两轮无新信息、工具重复调用、状态不变
- 循环检测：动作序列重复、目标反复改写
- 预算耗尽时的优雅降级（返回部分结果 + 说明缺什么）
- 终止必须可区分：成功 / 部分成功 / 失败 / 需人工介入

## 2.8 自我校验与反思
- 结果验证器：schema 校验、单元测试、规则断言、外部 API 复核
- Critic 模型 / 双模型互检
- 测试驱动（先写断言再执行）
- 事实核查与引用对齐
- 何时该"自我怀疑"：高不确定 + 高代价 → 转人工

## 2.9 单 Agent 失败模式清单
- 目标漂移（越走越偏）
- 工具误选 / 参数幻觉
- 过度探索（反复试错不收敛）
- 早停（还没做完就宣布完成）
- 上下文污染（把错误信息当事实）
- 无限循环 / 重复劳动
- 过度自信（不做校验就交付）
- 忽略用户约束（把系统提示当建议）

# 第 3 章 编排与多 Agent

## 3.1 Workflow / DAG / 状态机
- 顺序、并行、条件分支、循环、子流程
- 状态机建模：状态、转移、守卫条件
- 节点的幂等与补偿（可重试、可回滚）
- **图编排**（LangGraph 类）与代码编排的取舍
- 何时用 workflow 替代 Agent：路径确定、需审计、成本敏感

## 3.2 路由与分诊
- 意图分类 / 任务分诊 / 模型分诊
- 路由的误判成本与兜底路径
- Handoff（转人工、转专家 Agent）

## 3.3 Multi-Agent 拓扑
- Supervisor（主管–工人）
- Hierarchical（多层）
- Peer / Debate（辩论、投票）
- Pipeline（流水线）
- Swarm / 去中心化交接
- Blackboard（共享黑板）
- 每种拓扑的**适用条件**与典型开销

## 3.4 上下文与状态共享
- 消息传递 vs 共享内存 vs 共享文件系统
- **上下文隔离**：子 Agent 只看该看的，避免污染
- 结论回传格式（结构化摘要 > 原始对话）
- 责任边界与结果归属
- 一致性：并发写入冲突

## 3.5 多 Agent 失败模式
- 错误传播与放大（一个 Agent 的幻觉变成全队的事实）
- 上下文污染与"传话游戏"失真
- 无穷对话 / 互相推诿
- 成本与延迟爆炸（N 个 Agent × M 轮）
- 责任不清、无法归因
- **多数场景的正确解是：单 Agent + 好工具 + 好流程**

## 3.6 Human-in-the-loop
- 三种粒度：事前批准（pre-approval）/ 事中打断（interrupt）/ 事后审核（post-review）
- 审批点设计：不可逆操作、高金额、越权、低置信
- 超时策略与默认动作（拒绝 > 放行）
- 人的输入如何回注上下文（不能只回一句"继续"）
- 交接设计：给人工的摘要必须自包含
- UI 形态：审批卡片、diff 预览、轨迹回放

## 3.7 扩展协议与生态
- **MCP（Model Context Protocol）**：tools / resources / prompts，传输方式，服务端信任边界
- **Skill**：渐进式披露（metadata → 正文 → 资源），按需加载
- Plugin / 扩展机制
- `【拓展】` A2A（Agent-to-Agent）等 Agent 互联协议
- OpenAPI / Function Schema 的自动接入
- 第三方能力的供应链风险（后文安全章展开）

## 3.8 执行环境与沙箱
- 沙箱形态：容器 / gVisor / microVM / 进程隔离
- 网络隔离与白名单（外泄的主要通道）
- 文件系统隔离、临时盘、配额
- **Code Mode**：把代码当工具（比逐个工具调用更高效、更可组合）
- 浏览器自动化 / 计算机使用（Computer Use）
- 资源限制：CPU、内存、时长、磁盘
- 逃逸风险与最小权限

## 3.9 长任务、断点与恢复
- Checkpoint：状态快照的粒度与频率
- **Durable Execution**（Temporal 类）：把 Agent 循环当作可持久化工作流
- 断点续跑：幂等重放 + 已完成步骤跳过
- 事件溯源：以事件日志重建状态
- 长任务的心跳、超时、取消
- `【进阶】` 可重放（replay）与时间旅行调试

## 3.10 并发与调度
- 任务队列、优先级、公平性
- 限流、租约、分布式锁
- 多租户下的资源隔离
- 背压与排队时长的用户体验

# 第 4 章 知识与 RAG

## 4.1 数据接入与解析
- 格式：PDF、HTML、DOCX、PPT、Excel、扫描件、图片、代码库、数据库
- 版面分析（多栏、表格、页眉页脚、图注）
- OCR 与视觉理解的选择
- 表格提取（结构保留是难点）
- 元数据抽取：来源、时间、作者、权限、章节路径

## 4.2 清洗与归一化
- 去噪、去重（精确 / 近似 / 语义）
- 统一编码、语言识别、繁简转换
- 敏感信息识别与脱敏
- 内容质量过滤（低质页、导航栏、广告）

## 4.3 切片（Chunking）
- 固定长度 / 递归分隔 / 语义切片 / 按文档结构切片
- **父子块（small-to-big）**：小块检索、大块喂给模型
- Overlap 的取舍（召回 vs 冗余）
- 表格、代码、公式的特殊切片策略
- 元数据随块携带（过滤与引用依赖它）
- 切片的评估方式：切片质量差会伪装成"模型不行"

## 4.4 向量化（Embedding）
- 模型选型：维度、多语言、领域适配、成本
- 归一化与距离度量（cosine / dot / L2）
- 领域微调 embedding 的收益与成本
- 稀疏向量（SPLADE 类）与稠密向量的互补
- 向量漂移：换模型必须重建索引

## 4.5 索引与存储
- ANN 索引：HNSW / IVF / PQ / DiskANN，参数与召回率–延迟权衡
- 分片、副本、多租户命名空间
- 元数据索引与过滤（权限、时间、来源）
- 向量库选型：Milvus、Qdrant、Chroma、FAISS、Pinecone、pgvector、Elasticsearch
- 索引重建与灰度切换

## 4.6 查询理解（召回质量的上游）
- 查询改写 / 纠错 / 口语归一
- **查询分解**（复杂问题拆成多个子查询）
- 多查询扩展（multi-query）
- HyDE（假设性文档嵌入）
- 意图识别与槽位抽取
- 何时该**不检索**（闲聊、已有上下文、模型已知）

## 4.7 召回与融合
- 稠密检索 / 稀疏检索（BM25）/ 全文检索的互补性
- 混合检索与融合：**RRF**、加权求和、学习式融合
- 元数据过滤与 ACL 过滤（先过滤再检索，避免越权召回）
- 时效过滤与版本过滤
- 多路召回的数量配比与去重

## 4.8 Rerank 与精排
- Cross-encoder rerank、LLM rerank
- 多样性（MMR）与冗余控制
- 阈值截断（宁缺毋滥）
- Rerank 的成本–收益比

## 4.9 上下文组装
- 排序：相关性 vs 位置偏差（重要内容放首尾）
- 去重与合并（同一事实多源）
- 压缩（抽取式 / 生成式摘要）
- 引用标注与可点击溯源
- Token 预算与"留白"
- 冲突信息的呈现方式（并列 + 标注来源，而非静默择一）

## 4.10 生成与溯源
- 强制引用、引用与断言对齐
- 忠实度（faithfulness）与"无据不答"
- 拒答策略与拒答话术
- 答案可验证性设计

## 4.11 知识治理
- 增量索引与实时性
- 文档版本与索引版本
- 删除与撤销（含"被遗忘权"）
- 权限同步（源系统权限变更要传导到检索层）
- 知识冲突与时效性判定
- 更新触发机制（定时 / 事件 / 手动）

## 4.12 检索与 RAG 评估
- 检索侧：recall@k、MRR、nDCG、命中率
- 上下文侧：context precision / recall / relevancy
- 生成侧：faithfulness、answer relevancy、正确性
- 端到端：任务成功率、人工评分
- 分层定位：是没召回到、召回了没排上、排上了没用对，还是用了但生成错

## 4.13 Agentic RAG `【进阶】`
- 检索–评估–再检索的迭代循环
- 把检索做成工具，由 Agent 自主决定查什么
- 多知识源路由（文档库 / 数据库 / 图 / 网页）
- 自我反思式检索（判断"信息够不够"）
- 成本控制：迭代上限与提前停止

## 4.14 结构化知识与图谱
- **Text2SQL**：schema 注入、少样本示例、执行校验、只读权限、注入防护
- **Text2Cypher**：图查询生成与约束
- **GraphRAG**：实体抽取、关系构建、社区摘要、多跳问答
- **知识图谱 / Ontology**：本体设计、实体对齐、schema 约束
- 图库：Neo4j、NebulaGraph 等
- 领域知识治理：术语表、口径统一、指标定义
- 幻觉控制：schema 约束 + 执行结果校验 + 拒绝编造字段

## 4.15 多模态 RAG `【进阶】`
- 图表、示意图、扫描件的检索
- 版面感知的切片与召回
- 图文混合上下文的组装

## 4.16 缓存
- 精确缓存（query → answer）
- **语义缓存**（相似 query 复用）及其误命中风险
- 检索结果缓存、embedding 缓存
- 失效策略（知识更新时必须能失效）

## 4.17 工具与生态
- 向量库：Milvus / Qdrant / Chroma / FAISS / Pinecone / Elasticsearch / pgvector
- 框架：LlamaIndex、LangChain、Haystack
- 评测：RAGAS、DeepEval、TruLens
- 解析：Unstructured、PyMuPDF、Docling、Marker

# 第 5 章 系统工程与生产可靠性

## 5.1 可靠性原语
- 超时：分层超时（单次调用 / 单工具 / 单任务 / 端到端）
- 重试：指数退避 + 抖动、可重试错误分类（限流 vs 参数错 vs 服务错）
- **幂等**：幂等键设计、去重表、工具副作用的幂等包装
- 补偿事务：不可逆操作的 saga / 回滚路径
- 降级：模型降级、检索降级、功能降级、只读模式
- 熔断：错误率阈值、半开探测
- 限流与配额：按用户 / 租户 / 全局
- 背压：队列积压时的拒绝策略
- 失败隔离：单个坏工具不拖垮整个 Agent

## 5.2 状态与持久化
- 会话状态存储（Redis / DB）与 TTL
- 任务状态机持久化
- 中间产物存储（对象存储 + 引用）
- 一致性：多实例并发下的状态竞争

## 5.3 权限与隔离
- 认证：用户身份如何透传到工具层（**不能只信模型自述**）
- 授权模型：RBAC / ABAC / ReBAC
- 工具级最小权限：每个工具独立凭据，禁止万能 token
- 数据隔离：多租户行级隔离、命名空间隔离、物理隔离
- 检索层 ACL 过滤（越权召回是高频事故）
- 临时凭据与权限时效

## 5.4 审计与合规
- 审计日志：谁、何时、对什么、做了什么、结果如何
- 不可篡改与留存期
- 数据驻留与跨境
- PII 识别、脱敏、可删除权
- 合规框架映射（等保 / GDPR / 行业规范）
- 模型与数据的来源声明

## 5.5 可观测性
- 结构化日志：统一 trace_id / span_id / session_id / user_id
- **Trace 模型**：一次请求 = 根 span，模型调用 / 检索 / 工具 / 子 Agent 各为子 span
- OpenTelemetry GenAI 语义约定
- Metrics：QPS、成功率、P50/P95/P99、token 用量、工具错误率、检索命中率
- 成本归因：按用户 / 租户 / 功能 / 模型
- 采样策略：全量太贵，头部采样会丢长尾
- 告警设计：什么值得半夜叫醒人

## 5.6 可重放与调试
- 完整轨迹落盘（输入、上下文快照、模型输出、工具结果）
- **确定性重放**：固定外部依赖的返回值，复现同一 bug
- 时间旅行调试（回到第 N 步改写后重跑）
- 轨迹对比（改 prompt 前后 diff）
- 这是 Agent 工程效率的分水岭

## 5.7 发布与变更管理
- Prompt / 配置 / 工具的版本化与灰度
- 模型版本锁定（禁止上游静默升级）
- 影子流量与 A/B
- 回滚预案与一键降级
- 变更的评测门禁（见第 7 章）

## 5.8 成本工程
- 成本看板与预算告警
- 每任务成本 / **每成功任务成本**
- 成本优化优先级：缓存 > 路由 > 精简上下文 > 换模型
- 异常花费检测（死循环烧钱是真实事故）

## 5.9 容量与性能
- 并发上限与排队策略
- 冷启动（沙箱启动、模型加载）
- 首 token 延迟 vs 总时长
- 峰值流量与弹性

# 第 6 章 安全与对抗

> Agent 能调工具，注入就从"说错话"升级为"做错事"。这一章不能省。

## 6.1 威胁模型
- 参照 OWASP LLM Top 10 / Agentic 威胁清单
- 资产：数据、凭据、工具权限、用户信任
- 攻击面：用户输入、检索内容、工具返回、第三方插件、模型本身
- 攻击者目标：数据外泄、越权操作、拒绝服务、成本耗尽、内容污染

## 6.2 直接 Prompt Injection
- 越狱（jailbreak）与角色扮演绕过
- 系统提示泄露
- 指令覆盖与优先级欺骗

## 6.3 间接 Prompt Injection（最危险）
- 载体：检索文档、网页、邮件、PDF、代码注释、图片、工具返回值、MCP 服务
- 典型手法：隐藏文本、白字、HTML 注释、不可见 Unicode
- 防御：**把外部内容标记为数据而非指令**、内容隔离、来源标注、可疑指令检测

## 6.4 工具与执行风险
- 工具投毒（恶意 MCP server / 插件）
- 参数注入（SQL / 命令 / 路径穿越 / SSRF）
- 越权调用与权限提升
- 不可逆操作的滥用
- 资源耗尽（死循环、超大输出）

## 6.5 数据外泄
- 外带通道：Markdown 图片 URL、链接拼接、DNS 查询、工具参数
- 跨租户串数据
- 上下文被诱导回显
- 防御：出站白名单、渲染层过滤、敏感串检测

## 6.6 内容安全
- 输入审核与输出审核
- 有害内容分类与拦截
- 拒答率与可用性的平衡
- 审核模型本身的误判

## 6.7 隐私与合规
- PII 最小化：不该进上下文的绝不进
- 日志中的敏感信息
- 用户数据的可见、可导出、可删除
- 训练数据与用户数据的边界

## 6.8 防御体系（纵深）
- 最小权限 + 凭据隔离
- 沙箱 + 网络白名单
- 输入隔离与结构化封装
- 输出过滤与二次审核
- 危险操作人工审批
- 红队测试与注入回归集
- 双模型架构（执行模型 + 监督模型）

## 6.9 供应链
- 第三方 MCP / 插件的来源审查
- 依赖与镜像的可信性
- 模型来源与许可

# 第 7 章 评测与迭代

> 指标只是结果，方法才决定能不能持续变好。

## 7.1 评测分层
- 组件级：检索质量、工具选择、单步生成
- 轨迹级：步数、路径合理性、无效动作比例、成本
- 端到端：任务完成度、用户满意度
- 离线（可重复）vs 在线（真实分布）

## 7.2 指标全集
| 类别 | 指标 |
|---|---|
| 效果 | 任务成功率、完成质量分、回答准确性、幻觉率、拒答正确率 |
| 行为 | 工具调用准确率、参数正确率、平均步数、无效调用率、规划合理性 |
| 检索 | recall@k、MRR、nDCG、context precision/recall、faithfulness |
| 性能 | 首 token 延迟、端到端耗时、P50/P95/P99、吞吐 |
| 成本 | 每任务 token、每任务成本、**每成功任务成本**、缓存命中率 |
| 稳定性 | **pass^k**（连跑 k 次全对）、方差、超时率、崩溃率 |
| 安全 | 注入成功率、越权尝试拦截率、外泄检出率 |

## 7.3 数据集建设
- 金标准集（人工标注，小而精）
- 合成数据集（覆盖长尾，需去偏）
- **难例集**：从线上 badcase 沉淀
- 对抗集 / 红队集
- 回归集：每次改动必跑
- 数据版本与标注一致性（多人标注算 κ）

## 7.4 评测方法
- 规则断言（可判定的必须用规则，别用 judge）
- LLM-as-judge：评分标准（rubric）设计、位置偏差、长度偏差、自偏好
- 成对比较（pairwise）优于绝对打分
- Judge 校准：与人工标注的一致性验证
- 人工评测：抽样、盲评、标注规范
- 多次采样：pass@k（至少一次成功）vs **pass^k（k 次全成功）**，后者才反映生产可用性

## 7.5 在线实验
- A/B、灰度、影子流量
- 埋点与用户反馈（点赞/点踩/采纳率/改写率）
- 线上指标与离线指标的相关性验证（不相关就说明离线集不代表真实分布）
- 实验的统计功效与样本量

## 7.6 Badcase 归因
- 归因维度：检索没给 / 给了没用 / 工具选错 / 参数错 / 规划错 / 模型能力不足 / 数据本身错
- 归因流程：先看轨迹，再看单步，最后看模型
- 归因结果直接映射到改进动作（换模型 / 改 prompt / 改切片 / 加工具）

## 7.7 数据飞轮
- 线上日志 → 难例挖掘 → 标注 → 评测集扩充 / 训练数据
- 反馈闭环的延迟与自动化程度
- 避免"只优化评测集"的过拟合

## 7.8 平台与工具
- LangSmith、Langfuse、Arize Phoenix、W&B Weave
- RAGAS、DeepEval、OpenAI Evals、promptfoo
- 自建 vs 采购的取舍

# 附录 C：常见坑清单

1. 用多 Agent 解决单 Agent 加好工具就能解决的问题
2. 工具返回巨量原始数据，撑爆上下文
3. 没有最大步数，死循环烧钱
4. 把工具/检索返回的内容当指令执行
5. 检索层不做过权限过滤，越权召回
6. 只用向量检索，丢掉关键词精确匹配
7. 切片的锅让模型背
8. 幻觉归因错，去调 prompt 而不是补检索
9. 只测一次就上线，忽略 pass^k
10. 评测集与线上分布不一致
11. 用 LLM judge 评可规则判定的东西
12. 模型版本不锁定，上游静默升级导致回归
13. 没有 trace，出问题只能猜
14. 无法重放，改一行 prompt 全靠玄学
15. 重试不幂等，重复下单/重复扣费
16. 万能 token，所有工具共用一个高权限凭据
17. 长 Prompt 塞满规则，互相冲突
18. 用负面指令约束模型（"不要…"）
19. 忽略首 token 延迟，用户以为卡死
20. 没有降级路径，模型一挂全站挂
21. 成本没有看板，月底才发现账单爆炸
22. 人工审批给的信息不自包含，人看不懂
23. 子 Agent 回传原始对话而非结论，污染主线
24. 记忆无写入策略，什么都记导致噪音
25. 引用不做对齐，溯源点开是错的
