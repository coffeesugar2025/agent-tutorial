# 退款政策 Skill

## 何时启用

用户咨询以下任一主题时启用：退款/退货资格、退款运费由谁承担、退款到账时间、
"七天无理由"边界、生鲜/定制/虚拟商品能否退、退款进度查询。

## 执行步骤

1. **先查订单**：拿到订单号时调用 `get_order` 确认状态（`PAID`/`SHIPPED`/`FINISHED`/`CLOSED`）
   与签收时间；没有订单号则先请用户提供，或用 `list_orders` 让用户确认。
2. **再查政策**：调用 `search_knowledge`（`docTypes=["POLICY"]`）检索退款政策原文，
   只依据检索到的条款回答，不要凭记忆补充规则。
3. **判定资格**：调用 `check_refund_eligibility`，把 `eligible` / `reason` 作为结论主干。
4. **给下一步**：符合条件 → 说明如何发起退款（需人工审批的动作不要直接承诺已提交）；
   不符合 → 说明原因 + 可行替代方案（换货、维修、平台介入）。
5. **超范围**：涉及金额争议、投诉、平台仲裁 → 调用 `escalate_to_human`。

## 判定口径（以知识库为准，以下为检索提示词）

| 场景 | 结论要点 |
|---|---|
| 签收 7 天内、非例外品类 | 支持无理由退货，商品需不影响二次销售 |
| 商品质量问题 | 支持退换，运费由商家承担 |
| 无理由退货 | 运费默认由买家承担，另有约定从其约定 |
| 生鲜 / 定制 / 虚拟商品 / 已拆封的个人护理品 | 不支持无理由退货（质量问题除外） |
| 退款到账 | 商家审核通过后 1-3 个工作日原路退回，银行处理时间另计 |

## 回答模板

> 已核实你的订单 {orderNo}（{status}）。根据平台《退款政策》：
> 1. 是否符合：{结论 + 依据条款}
> 2. 运费：{承担方 + 依据}
> 3. 时效：{预计到账时间}
> 4. 下一步：{具体操作或转人工}

## 禁止事项

- 不要承诺"一定全额退款""立刻到账"等超出政策的结论；
- 不要在未调用工具的情况下编造订单状态、物流节点或退款单号；
- 不要输出收件人手机号、完整地址等 PII（引用订单信息时按脱敏后的字段回答）；
- 不要引导用户绕过审批流程。

## 引用要求

所有政策结论至少给出一条知识库引用（标题 + `chunkId`），
格式：`依据：《退款政策》第 2 条（chunkId=88）`。
