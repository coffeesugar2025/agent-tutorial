# 测试用例

> 目标：**两套后端行为一致、离线可跑、写操作零事故**。
> 本文是测试设计与验收的**事实源**：用例 ID 一旦分配不再复用；契约比对项与 `docs/03-API契约.md` 同步演进。
> 约定：所有用例默认 `MOCK_LLM=true` + `EMBEDDING_PROVIDER=hash` + `VECTOR_STORE=memory`，不依赖外网与真实 API Key。

### 4.2 判定规则

| 规则 | 说明 |
|---|---|
| 结构 | 字段名**完全相同**（camelCase），缺失必填字段 = 失败，多余字段 = 失败 |
| 类型 | number/string/boolean/array/object 分类必须一致；`null` 仅允许出现在契约声明可空的字段 |
| 枚举 | `agentType`/`risk`/`status`/`finishReason`/`docType`/`visibility` 取值必须落在 03 的枚举内 |
| 状态码 | HTTP 状态码与 `code` 的映射关系必须一致 |
| SSE | 解析两端原始字节流，按 `event:` 分组；顺序违规 = 失败 |
| 容忍 | 文案、时间、id、token 数、检索分数、排序细节不比对 |

### 4.3 允许的差异（不是 bug）

| 差异 | 原因 |
|---|---|
| Milvus 接入方式（pymilvus vs REST v2） | 语言生态不同，行为一致 |
| 线程模型（asyncio vs 线程池） | 语言惯用法 |
| 数值精度最后一位 | 浮点/四舍五入差异 |
| 错误 message 文案 | 契约只约束 code，不约束文案 |
| `replayable` 等扩展字段 | 03 中标注为可选 |

### 8.4 pass@k 与 pass^k

- **pass@k**（能力上界）：每题生成 k 次，**至少 1 次**通过即算通过。

  \[
  \text{pass@}k=\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\left[\exists j\in[1,k]:\ \text{case}_i^{(j)}\text{ 通过}\right]
  \]

  无偏估计（采样 n 次取 k）：

  \[
  \text{pass@}k=\frac{1}{N}\sum_{i=1}^{N}\left(1-\frac{\binom{n-c_i}{k}}{\binom{n}{k}}\right)
  \]

  其中 \(c_i\) 为第 i 题通过的采样次数。

- **pass^k**（稳定性下界）：每题 k 次**全部**通过才算通过。

  \[
  \text{pass}^k=\frac{1}{N}\sum_{i=1}^{N}\prod_{j=1}^{k}\mathbb{1}\left[\text{case}_i^{(j)}\text{ 通过}\right]
  \]

  实现上等价于 `repeat=k` 时"该用例 attempts=k 且 passed=k"，直接落 `eval_run.pass_k`。

> 解读：pass@k 高说明"能做对"，pass^k 高说明"稳定做对"。发布门禁看 **pass^k**，能力评估看 pass@k。
