## 0.1 该不该做 Agent：决策边界

**要点**

| 信号 | 倾向 Agent | 倾向 Workflow / 规则 |
|---|---|---|
| 任务路径是否可穷举 | 长尾、说不清 | 能画出流程图 |
| 是否有可验证反馈 | 有测试/校验/人工确认 | 无 |
| 错误代价 | 可撤销、可回滚 | 不可逆、强审计 |
| 调用频率 | 低频、高价值 | 高频、低价值 |
| 延迟要求 | 秒级可接受 | 百毫秒级 |

写代码时的落地：**默认用 Workflow，只在需要"模型决定下一步"时才启用 Agent**。本项目把这一判断固化成配置项 `AGENT_ENGINE`，并让 Supervisor 只做**一次**路由，不做多 Agent 互调。

**Python** · `app/config.py` + `app/agents/supervisor.py`

```python
# 引擎可选 native / langchain，避免把"是否自主"写死在代码里
@field_validator("agent_engine")
@classmethod
def _check_engine(cls, value: str) -> str:
    allowed = {"native", "langchain"}
    if value.lower() not in allowed:
        raise ValueError(f"AGENT_ENGINE 只能是 {sorted(allowed)}")
    return value.lower()
```


**Java** · `agent/SupervisorAgent.java`

```java
public Route route(String question) {
    String q = question == null ? "" : question.toLowerCase(Locale.ROOT);
    if (containsAny(q, "报表", "销售额", "gmv", "营收", "统计", "趋势", "转化率")) {
        return new Route(AgentType.OPS, "经营分析意图");
    }
    if (containsAny(q, "订单", "物流", "快递", "退款", "退货", "售后", "投诉")) {
        return new Route(AgentType.SERVICE, "订单售后意图");

    return new Route(AgentType.SHOPPING, "商品导购意图");
```

**坑 / 差异**

- **两端路由策略不同**：Python 是「模型结构化输出优先 + 关键词兜底」，Java 是**纯规则**。Java 省一次模型调用、100% 可复现，代价是覆盖不了同义表达；生产建议按流量成本取舍，本项目刻意保留两种以做对比。
- 不要把「多步」当成「多 Agent」。本项目 4 个 Agent 中，只有 3 个子 Agent 真正执行，Supervisor 零工具。

## 1.1 多模型接入：统一工厂 + 懒加载

**要点**

- 供应商差异（DeepSeek / 千问 / OpenAI / Ollama）收敛在**一个工厂**里；
- **懒加载**：没配 Key 就抛 `ProviderUnavailable`，由上层 fallback 切下一个，而不是启动即崩；
- 千问、Ollama 都走 **OpenAI 兼容模式**，避免为每家写一套协议。

**Python** · `app/llm/providers.py:build_chat_model`

```python

    if provider == "qwen":                                  # 阿里云 DashScope 兼容端点
        return _openai_compatible(model=resolved_model, base_url=settings.dashscope_base_url,
                                  api_key=settings.dashscope_api_key, temperature=temp)
    ...
    raise ProviderUnavailable(f"未知的供应商: {provider}")
```

**Java** · `llm/OpenAiCompatibleProvider.java`（真正用 LangChain4j 的 `OpenAiChatModel`）

```java
public Result chat(Request request) {
    if (!configured()) {
        throw new LlmException(name + " 未配置 baseUrl / apiKey / model");
    }
    List<ChatMessage> messages = toLangChain4jMessages(request.messages());
    ChatResponse response = model().chat(ChatRequest.builder().messages(messages).build());

    String text = extractText(response);
    if (text == null || text.isBlank()) {
        throw new LlmException(name + " 返回空内容");
    }
    int promptTokens = 0, completionTokens = 0;
    try {
        var usage = response.tokenUsage();                  // 不同小版本可能为 null
        if (usage != null) {
            promptTokens = usage.inputTokenCount();
            completionTokens = usage.outputTokenCount();
        }
    } catch (RuntimeException ignored) { }
    if (promptTokens <= 0) promptTokens = estimatePromptTokens(request);
    if (completionTokens <= 0) completionTokens = TokenEstimator.estimate(text);
    return new Result(text, promptTokens, completionTokens, name, model,
                      System.currentTimeMillis() - start);
}

private ChatLanguageModel model() {                         // 双检锁懒加载
    ChatLanguageModel local = delegate;
    if (local == null) {
        synchronized (this) {
            if ((local = delegate) == null) {
                local = OpenAiChatModel.builder()
                        .baseUrl(baseUrl).apiKey(apiKey).modelName(model)
                        .timeout(Duration.ofSeconds(timeoutSeconds)).maxRetries(0)
                        .build();
                delegate = local;
            }
        }
    }
    return local;
}
```

**坑 / 差异**

- `maxRetries(0)` 是刻意的：**重试统一由 fallback 层做**，否则框架重试 × 业务重试 = 指数级放大。
- Java 端把 `ChatLanguageModel` 藏在 `LlmProvider` 接口后：升级 LangChain4j 不会波及业务代码，代价是多一层薄适配。
- `tokenUsage()` 在部分兼容网关下返回 null，必须兜底估算，否则计费为 0。

## 1.2 Token 估算：没有 tokenizer 也要能算钱

**要点**：真实 tokenizer（tiktoken）需要联网下词表，容器里常常不可用。工程上要一个**确定性、可单测**的估算器，误差可接受（±20%）即可，因为它只用于预算与降级判断，不用于计费对账。

**Python** · `app/common/tokens.py`

```python
def estimate_tokens(text: str | None) -> int:
    """中日韩按 1 字 ≈ 1 token，其余按 4 字符 ≈ 1 token 估算。"""
    if not text:
        return 0
    cjk = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    other = len(text) - cjk
    return cjk + max(1, other // 4)

def fit_texts(texts: Sequence[str], budget: int, separator: str = "\n\n") -> str:
    """按预算拼装多段文本，超限截断——上下文组装的核心工具。"""
    ...
```

**Java** · `common/TokenEstimator.java`

```java
public static int estimate(String text) {
    if (text == null || text.isEmpty()) return 0;
    int cjk = 0;
    for (int i = 0; i < text.length(); i++) {
        char c = text.charAt(i);
        if (c >= '\u4e00' && c <= '\u9fff') cjk++;
    }
    int other = text.length() - cjk;
    return cjk + Math.max(1, other / 4);
}
```

**坑 / 差异**：同一段中文，两端估算结果一致（都按 1 字 1 token），这是**契约测试能对齐**的前提；若换用真实 tokenizer，两端必须锁同一个词表版本。

## 1.3 路由与级联：把"用哪个模型"变成数据

**要点**

- **任务分类 → 档位（fast / strong）→ 候选链**，路由是可配置的数据，不是散落的 if；
- **级联**只在 fast 结果"不够好"时发生一次，不递归；
- 候选链顺序：`主供应商 fast → 主供应商 strong → 各兜底供应商`。

**Python** · `app/llm/router.py`

```python
class TaskClass(str, Enum):
    ROUTE = "route"        # 意图路由（短、高频、便宜）
    CHAT = "chat"          # 主对话
    TOOL_REASON = "tool"   # 工具调用推理
    RERANK = "rerank"
    JUDGE = "judge"
    SUMMARY = "summary"
    TEXT2SQL = "text2sql"
    COMPLEX = "complex"

def route(task: TaskClass, agent_type: str | None = None) -> ModelChoice:
    tier = task.tier                                    # fast / strong
    if agent_type == "OPS" and task in (TaskClass.TEXT2SQL, TaskClass.COMPLEX):
        tier = STRONG                                   # 经营分析统一上强模型
    return make_choice(settings.effective_primary, tier)

def escalate(choice: ModelChoice) -> ModelChoice:
    """fast → strong，同一供应商内的更强模型。"""
    return choice if choice.tier == STRONG else make_choice(choice.provider, STRONG)

def candidates(task: TaskClass, agent_type: str | None = None) -> list[ModelChoice]:
    primary = route(task, agent_type)
    chain = [primary]
    if primary.tier == FAST:
        chain.append(escalate(primary))
    for provider in settings.fallback_providers:
        if provider != primary.provider:
            chain.append(make_choice(provider, primary.tier))
    return _dedup(chain)
```

**Java** · `llm/ModelRouter.java` + `llm/FallbackChain.java`

```java
public LlmProvider.Result chat(List<LlmProvider.Message> messages) {
    LlmProvider.Request request = new LlmProvider.Request(messages, temperature, maxTokens);
    return chat(request);
}

public LlmProvider.Result chat(LlmProvider.Request request) {
    for (LlmProvider provider : factory.ordered()) {        // 已按优先级排好
        if (!breaker.allowRequest(provider.name())) continue;   // 熔断中直接跳过
        long start = System.currentTimeMillis();
        try {
            LlmProvider.Result result = provider.chat(request);
            breaker.recordSuccess(provider.name(), System.currentTimeMillis() - start);
            return result;
        } catch (RuntimeException e) {
            breaker.recordFailure(provider.name());
        }
    }
    throw new LlmException("所有模型供应商均不可用");
}
```

**坑 / 差异**

- Python 用 `candidates()` 生成**候选链**再逐个 try；Java 用 `factory.ordered()` + 循环。语义一致，实现风格不同。
- 级联判定（"fast 结果够不够好"）在 Python 里由 `LLMCallResult` 的 finish_reason/长度/结构化解析结果决定，**没有**做自动二次调用——因为自动升级会让成本翻倍且难归因。生产环境建议按 A/B 打开。

## 1.4 熔断：防止一个坏供应商拖垮全部请求

**要点**：`CLOSED → (连续失败≥3) → OPEN → (冷却 30s) → HALF_OPEN → 探测成功回到 CLOSED`。

**Python** · `app/llm/fallback.py:CircuitBreaker`

```python
class CircuitBreaker:
    def __init__(self, name: str, failure_threshold: int = 3, recovery_seconds: float = 30.0):
        self.name = name
        self.failure_threshold = max(failure_threshold, 1)
        self.recovery_seconds = recovery_seconds
        self._failures = 0
        self._state = CircuitState.CLOSED

    def allow(self) -> bool:
        self._maybe_half_open()                 # OPEN 且已过冷却期 → HALF_OPEN
        return self._state is not CircuitState.OPEN

    def record_failure(self, reason: str) -> None:
        self._failures += 1
        if self._failures >= self.failure_threshold:
            self._state = CircuitState.OPEN
            self._opened_at = time.time()

    def record_success(self) -> None:
        self._failures = 0
        self._state = CircuitState.CLOSED
```

**Java** · `llm/CircuitBreaker.java`

```java
private static final int DEFAULT_FAILURE_THRESHOLD = 3;
private static final long DEFAULT_OPEN_MILLIS = 30_000L;

public boolean allowRequest(String name) { ... }        // OPEN 且未到冷却 → false
public void recordFailure(String name) { ... }          // 连续失败达阈值 → OPEN
public void recordSuccess(String name, long latencyMs) { ... }
public String state(String name) { return CLOSED / OPEN / HALF_OPEN; }
```

**坑 / 差异**

- 熔断器必须**按供应商实例化**，不能全局一个；否则千问挂了会把 DeepSeek 也熔断。
- `HALF_OPEN` 要限制"只放一个探测请求"，否则恢复瞬间被打爆。
- 阈值两端已统一为 **3 次 / 30s**（此前 Java 是 5 次，已修正）。

## 1.5 结构化输出：别用正则解析自然语言

**要点**：路由、重排、裁判这类"要机器可读结论"的调用，必须用**结构化输出**，而不是 `"我认为应该转给 SERVICE"` 再拿正则抠。

**Python** · `app/llm/fallback.py:LLMClient.structured` + `app/agents/supervisor.py`

```python
class RouteDecision(BaseModel):
    agent_type: str = Field(description="SHOPPING / SERVICE / OPS 三选一")
    reason: str = Field(default="", description="不超过 30 字的中文理由")
    confidence: float = Field(default=0.5, ge=0.0, le=1.0)

async def structured(self, messages, schema, *, task=TaskClass.ROUTE):
    for choice in candidates(task):
        try:
            model = providers.build_chat_model(choice.provider, choice.model)
            return await model.with_structured_output(schema).ainvoke(messages)
        except Exception:
            continue                       # 逐候选降级，全部失败才抛
    raise LLMUnavailable("结构化输出失败")
```

**Java** · `agent/ToolCallParser.java` + `eval/EvalJudge.java`

```java
// Java 端没有 with_structured_output 等价物，统一用「严格 JSON 文本协议 + 解析容错」
public Optional<ToolCall> parse(String text) {
    if (text == null || text.isBlank()) return Optional.empty();
    int start = text.indexOf('{');
    int end = text.lastIndexOf('}');
    if (start < 0 || end <= start) return Optional.empty();
    try {
        JsonNode node = JsonUtil.mapper().readTree(text.substring(start, end + 1));
        String name = node.path("tool").asText(null);
        if (name == null || name.isBlank()) return Optional.empty();
        Map<String, Object> args = JsonUtil.mapper().convertValue(
                node.path("args"), new TypeReference<Map<String, Object>>() {});
        return Optional.of(new ToolCall(name, args));
    } catch (Exception e) {
        return Optional.empty();           // 解析失败 → 当作最终答案，不炸
    }
}
```

**坑 / 差异**

- Python 的 `with_structured_output` 底层会注入 JSON Schema 并强校验；Java 端是**文本协议**，所以 `parse` 必须"抠第一个 `{` 到最后一个 `}`"并容忍脏字符。
- 无论哪种，**解析失败都必须有兜底路径**（本项目：当作最终答案 / 走关键词路由），不能让一次格式抖动变成 500。

## 1.6 成本核算：先算清"每成功任务成本"

**要点**

- 单价表按 `分/百万 token` 存，避免浮点误差，全部用整数分；
- **缓存命中 token 单独计价**（通常 10%）；
- 输出两个指标：`cost_per_task` 与 **`cost_per_success`**，后者才是真实效率。

**Python** · `app/llm/cost.py`

```python
def compute_cost_cents(choice: ModelChoice, usage: TokenUsage) -> int:
    price_in, price_out, price_cached = price_of(choice.model)
    fresh = max(0, usage.prompt_tokens - usage.cached_tokens)
    raw = (
        fresh / 1_000_000 * price_in
        + usage.cached_tokens / 1_000_000 * price_cached
        + usage.completion_tokens / 1_000_000 * price_out
    )
    return max(1, int(round(raw * 100))) if raw > 0 else 0   # 最低 1 分，避免 0 掩盖调用
```

**Java** · `llm/CostCalculator.java`

```java
public int costCents(String model, int promptTokens, int completionTokens) {
    Price price = prices.getOrDefault(model, Price.DEFAULT);
    double raw = promptTokens / 1_000_000.0 * price.inCents()
               + completionTokens / 1_000_000.0 * price.outCents();
    return raw <= 0 ? 0 : Math.max(1, (int) Math.round(raw));
}
```

**坑 / 差异**

- `max(1, …)` 是刻意的：很多小调用会算出 <1 分，四舍五入成 0 会让"成本看板"看起来免费，掩盖真实增长。
- Mock 模型价格必须为 0（否则测试会写脏账单），但**调用次数仍要记**，用于验证埋点。

## 双端差异汇总（本册）

| 项 | Python | Java | 是否需要统一 |
|---|---|---|---|
| 路由方式 | 模型结构化输出 + 关键词兜底 | 纯关键词规则 | 否（刻意对比），但需在文档标注 |
