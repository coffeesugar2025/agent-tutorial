# 代码能力标注规范

> 目的：在源码里直接标出「这段代码实现了哪个 Agent 能力」，让代码、文档、评审共用同一套编号。
>
> 编号与 [`10-Agent通用能力框架.md`](10-Agent通用能力框架.md) 的 18 个能力域**一一对应**，可互相跳转。

---

## 一、两层标注体系

代码里是**两层**标注，互补而非重复：

| 层级 | 位置 | 回答的问题 | 数量 |
|---|---|---|---|
| **文件级横幅** | 文件头部（docstring / package 之后） | 这个文件**整体**承担哪些能力？ | 251 个文件全覆盖 |
| **函数级注释块** | 关键函数正上方 | 这个函数**具体**实现了什么？ | 79 个块 / 237 行 |

### 1.1 文件级横幅格式

| 语言 | 格式 |
|---|---|
| Python | `# ═══════ 文件级能力标注 ═══════`<br>`# [CAP-12] 检索增强 RAG`<br>`# 职责：文档切片：递归切分 + 父子块（中文友好）`<br>`# 能力编号与规范见 docs/11…` |
| Java | `// ═══════ 文件级能力标注 ═══════`<br>`// [CAP-12] 检索增强 RAG`<br>`// 职责：切片器：按句子边界累积…`<br>`// 能力编号与规范见 docs/11…` |

**放置规则**

- Python：放在**模块 docstring 之后**——放前面会让 `__doc__` 变成 `None`；
- Java：放在 **`package` 声明之后、import 之前**；
- 职责行取自文件原有 docstring / Javadoc 首行，保证不是千篇一律的模板话。

### 1.2 函数级注释块格式

三行：能力域 + 本处职责 + 域内约束。

```python
# ──────── [CAP-12] 检索增强 RAG ────────
#   本处：RRF 融合（抗分数量纲差异）
#   域约束：任一环节失败必须降级并标记 degraded，不允许静默返回空结果
def rrf_fuse(dense: list[Hit], sparse: list[Hit], k: int = RRF_K) -> list[tuple[Hit, float]]:
```

**为什么是三行而不是一行**：单行只能说"这是什么"，说不出"为什么这么做"和"不能怎么改"。
第三行的**域约束**是同一能力域所有实现共享的硬规则（例如 CAP-14 的"降级必须可观测"），
改代码时先看这行就不会踩到设计红线。

**放置规则（函数级）**

1. 放在**函数 / 方法 / 类**定义行的正上方，缩进与定义行对齐；
2. **必须放在 Javadoc（Java）与装饰器（Python）之上**——否则 Javadoc 会失去与方法的关联，
   IDE 文档弹窗会失效；
3. 一个函数实现多个能力时，只标**最主要**的那个；
4. 已有块不重复添加（幂等）。

## 四、怎么用（grep 速查）

```bash
# 1) 看某个能力在整个项目里的落点（函数级 + 文件级都会命中）
rg -n "\[CAP-12\]" .

# 2) 只看 Python 侧
rg -n "\[CAP-10\]" backend-python/

# 3) 统计各能力域的标注数
rg -o "\[CAP-\d{2}\]" . | sort | uniq -c | sort -rn

# 4) 找出某个文件实现了哪些能力
rg -o "\[CAP-\d{2}\]" backend-python/app/agents/runtime.py | sort -u

# 5) 只看文件级横幅（快速盘点某目录下每个文件的职责）
rg -l "文件级能力标注" backend-python/ | head -20

# 6) 抽查某个文件的横幅内容
rg -A4 "文件级能力标注" backend-java/src/main/java/com/xingtu/agent/rag/Chunker.java

# 7) 反向检查：哪些能力域还没被标注（预期为 0）
for i in $(seq -w 1 18); do
  c=$(rg -c "\[CAP-$i\]" . 2>/dev/null | wc -l)
  [ "$c" -eq 0 ] && echo "CAP-$i 未标注"
done
```

> Windows PowerShell 等价写法：
> ```powershell
> Select-String -Path (Get-ChildItem -Recurse -File -Include *.py,*.java) -Pattern '\[CAP-(\d{2})\]' |
>   ForEach-Object { $_.Matches.Groups[1].Value } | Group-Object | Sort-Object Name
> ```

## 六、维护约定

1. **新增能力**：先在 `docs/10` 的 18 域里确认归属，再在代码里打 `[CAP-xx]`，最后在本文第二节补一行；
2. **改动能承载多能力**：只标主能力，其余在 PR 描述里说明；
3. **删除代码**：同步删标签，避免 grep 指向不存在的实现；
4. **CI 校验（建议补）**：跑一遍第四节第 5 条，确保 18 个域都有标注，防止文档与代码漂移。

## 七、覆盖范围：全部 Python / Java 文件

**现在没有任何一个 Python / Java 文件是"没标注"的。**

| 类别 | 数量 | 标注方式 |
|---|---|---|
| Python 源码（含 tests / scripts） | 104 | 文件级横幅（100%）+ 函数级块 64 处 |
| Java 源码（main + test） | 147 | 文件级横幅（100%）+ 函数级块 15 处 |
| **合计** | **251** | 251 个横幅 + 79 个函数级块 |

### 支撑类文件怎么标

DTO、Repository、配置、脚手架这些**不实现能力但服务于能力**的文件，
横幅里会带 `（支撑）` 标记，能力编号取自它服务的域：

```python
# ═══════ 文件级能力标注 ═══════
# [CAP-01] 交互协议  |  [CAP-14] 可靠性/降级  （支撑）
# 职责：统一响应信封与分页结构。
```

这样 grep `CAP-12` 时，既能看到 RAG 的实现（函数级块），也能看到为它服务的数据访问层（文件级横幅），
不会漏掉链路。

### 不在标注范围的

| 类别 | 原因 |
|---|---|
| 前端 `frontend/**` | 前端是能力的**消费方**；若需要可另按 CAP-01 / CAP-10 标注 |
| 部署 `deploy/**`、`docs/**` | 运维与文档产物，非代码能力 |
| SQL / YAML / 配置样例 | 数据与配置，非逻辑 |
