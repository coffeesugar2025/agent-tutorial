# 双后端契约 · Python / Java

## 一、为什么能「前端共用」

前端 `src/api/backend.ts` 只读一个环境变量 `VITE_BACKEND=python|java`，
把请求打到 `/api/py/*` 或 `/api/java/*`；nginx 分别反代到 8000 / 8080。
**两套后端实现同一组路径与响应字段**，业务代码零改动。

```
Vue3 ── /api/py/* ──> nginx ──> FastAPI  :8000 (LangChain 1.5.2 / Python 3.12)
    └── /api/java/* ──────────> SpringBoot:8080 (LangChain4j 1.24.0 / JDK17)
                                     │
                     MySQL · Redis · RabbitMQ · Milvus
```

## 二、共享路径（40 条）

完整机器可读清单在 `tests/contract/openapi-contract.json`，由
`tests/contract/check_contract.py` 静态比对两端路由声明；CI 必跑。

| 组 | 路径 | 关键字段 |
|---|---|---|
| 基础 | `/health` `/v1/tools` | `status` `tools` |
| 能力 | `/v2/capabilities` `/v2/plan` `/v2/workflow/run` `/v2/multi-agent/chat` | `modules` `trace` `stage` `agents_used` |
| RAG | `/v2/rag/query` `/v2/models/route` | `answer` `citations` `plan` |
| 审批 | `/v2/approvals*` | `stats` `status` |
| 加固 | `/v3/*`（24 条） | `decision` `retryable` `visible` `aggregate_pass_pow_k` |

Python 独有：`/metrics`。Java 独有：`/actuator/prometheus`。差异在契约文件里显式登记，不算不一致。

> **重要限定（复盘补充）**：`check_contract.py` 只做**路径存在性**静态比对，
> 不比对响应字段取值或业务语义。「40 条路径 PASS」不等于「两端行为一致」。
> Java 侧是**契约镜像**，业务真值以 Python 为准；下列端点为 mock/桩实现：
>
> | 端点 | Java 侧状态 | 说明 |
> |---|---|---|
> | `/v3/models/chat` | mock 常量 | 不调真实模型（`LLM_MODE=mock` 下合理） |
> | `/v3/security/redteam` | 静态列表 | Python 侧才实跑 5 条注入回归 |
> | `/v3/rag/evaluate` | 固定指标 | 未接 Java 侧分层评估计算 |
> | `/v3/replay/compare` | 恒 `identical=true` | 未实现轨迹 diff |
> | `/v3/prompts` `/v3/prompts/register` | 假 hash / 忽略入参 | 未接 Java 侧 PromptRegistry |
> | `/v3/tools/specs` `/v3/infra` | 静态描述 | 非运行时反射 |
> | `/v3/capabilities` | 静态自述 | 两端均为描述性文本 |
>
> 另有两处已在代码层修复：`RagRequest` 现在同时接受 `top_k` 与 `topK`
> （前端 `CitationView.vue` 发的是 `top_k`）；`/v3/replay/record` 现在返回 `frames`。

## 三、语义对齐表

| 能力 | Python | Java |
|---|---|---|
| Agent Loop | `create_agent` → CompiledStateGraph | `@AiService` + `@Tool` 自动循环 |
| 会话记忆 | `InMemorySaver` + `thread_id` | `@MemoryId` + `MessageWindowChatMemory` |
| 多模型 | `infra/llm_gateway.py` 统一 OpenAI 兼容 | `LlmConfig` + `LlmRouter`（单一 @Primary ChatModel） |
| RAG | `capabilities/rag/*` + MilvusAdapter | `RagService` + `langchain4j-milvus` |
| 注入防护 | `hardening/injection.py` | `InjectionGuard`（同一规则集） |
| ACL | `hardening/acl.py` | `AclService`（同一 expr 语义） |
| 评测 | `EvalSuite` / `stability.pass^k` | `ObservabilityService.evalStability` |
| MQ | `MessageBus` (pika/inproc) | `AgentEvents` (Spring AMQP) |
| 配置 | `infra/settings.py` | `application.yml` |

## 四、Java 侧已核实的版本坑（写进代码注释）

1. **1.24.0 存在**（2026-11-18 稳定版），BOM `dev.langchain4j:langchain4j-bom:1.24.0`。
2. **1.x 改名**：`ChatLanguageModel` → `ChatModel`；`StreamingChatLanguageModel` → `StreamingChatModel`。
   照 2024 教程写会「找不到符号」。
3. **两个 starter 都要显式声明**：`langchain4j-spring-boot-starter` 是 `@AiService/@Tool`
   自动配置入口，只加 open-ai starter 注解完全不生效。
4. **多个 ChatModel bean 类型注入会启动失败**：本仓库只暴露一个 `@Primary`，
   其余供应商放进 Map 由 `LlmRouter` 显式选择，`@AiService(wiringMode=EXPLICIT, chatModel="primaryChatModel")`。
5. Boot 3.x 用无后缀 starter，Boot 4 才用 `-spring-boot4-starter`；本项目锁 Spring Boot 3.3.6 + JDK17。
6. 1.24.0 新增 `langchain4j-test` 公开 ChatModel/EmbeddingModel Mock，离线单测不花 token。

## 五、契约校验

```bash
python3 tests/contract/check_contract.py           # 静态
python3 tests/contract/check_contract.py --live    # 两端在线时探测
docker compose -f infra/docker-compose.yml up -d   # 起真实环境
bash infra/scripts/smoke.sh
```
