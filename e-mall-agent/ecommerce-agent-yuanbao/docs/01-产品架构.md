# 产品架构 · 小栈电商智能体（双后端版）

## 一、产品定位

面向电商客服/导购场景的**生产级 Agent 系统**：一个 Vue3 前端，两套同契约后端
（Python LangChain 1.5 / Java LangChain4j 1.24），共享 MySQL、Redis、RabbitMQ、Milvus
与多家大模型。默认 `AGENT_MODE=mock` 零 Key 可跑，切 `real` 即接 DeepSeek / 千问 / GLM。

**产品形态以 Copilot + Chat 为主，Autonomous 仅覆盖只读任务**：
涉及下单、退款、改址的写操作一律进 HITL 审批，不自动执行（对应总纲 0.4 决策权分配）。

## 二、用户与场景

| 角色 | 诉求 | 主要能力 |
|---|---|---|
| 消费者 | 找商品、算券后价、查订单、问退货 | 单 Agent + 10 个只读工具 + RAG 政策问答 |
| 客服坐席 | 快速核实事实、看引用、转人工 | Trace 回放、引用溯源、审批中心 |
| 运营/算法 | 改 prompt、看成功率/成本、回归 | 评测看板、成本看板、CI 门禁、灰度发布 |
| 平台工程 | 双后端、多模型、多租户 | 契约层、ACL、适配器、部署脚本 |

## 三、功能矩阵

| 域 | 功能 | 前端 | 端点 |
|---|---|---|---|
| 导购 | 六场景对话、商品卡/价格卡/订单卡 | 主聊天区 + 卡片 | `/v1/chat` `/v1/chat/sync` |
| 知识 | 政策问答、混合检索、引用溯源、拒答 | CitationView | `/v2/rag/query` |
| 编排 | ReAct / Plan-and-Solve / 状态机 / 多 Agent | CapabilityPanel | `/v2/plan` `/v2/workflow/run` `/v2/multi-agent/chat` |
| 审批 | 三粒度 HITL、超时拒绝、自包含摘要 | ApprovalCenter | `/v2/approvals/*` `/v3/hitl/*` |
| 运维 | 成本、评测、轨迹回放、能力矩阵 | EvalDashboard / CostDashboard / TraceReplay | `/v3/*` |
| 平台 | 双后端切换、多模型路由、租户隔离 | 顶部后端标识 | `/v3/models/*` `/v3/infra` |

## 四、核心用户旅程

1. 用户问「星野 Pro 用 FULL100 券后多少钱」→ 单 Agent 选 `calculate_price` →
   `ToolMessage` 回填 799.00 → 卡片渲染（不让模型复述数字）。
2. 用户问「价保政策」→ 查询理解 → ACL 下推 → Milvus 混合检索 + Rerank →
   `[1]` 引用编号 → 抽取式作答；资料不足直接拒答。
3. 用户说「帮我退款」→ 风险判定为写操作 → 挂起审批单 → 坐席在审批中心看到
   **自包含摘要**（工具/参数/风险/轨迹号）→ 批准/拒绝/改写 → resume 执行（幂等）。
4. 运营改了一行 system prompt → 注册 canary 版本 → 10% 灰度 →
   跑 Golden Case + pass^k + 三重门禁 → 通过才 promote → 轨迹 diff 可回溯。

## 五、产品边界（明确不做）

- 不自动执行退款/下单/改址（只登记意向或走审批）。
- 不承诺「RAG 消除幻觉」：只承诺引用可追溯 + 无据不答 + 忠实度校验。
- 不在本仓库训练模型：SFT/LoRA/DPO 等只提供任务契约，交外部 GPU 平台。
- 不把 10 个 MCP 工具升级成写工具；只读边界是产品承诺。

## 六、演示数据

8 商品 / 4 券 / 4 订单 / 5 政策，统一在 `app/services/catalog.py`（Python）与
`OrderTools`（Java）派生，MySQL seed 与 Milvus 语料同源，避免三处事实打架。
