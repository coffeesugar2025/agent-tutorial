```
┌──────────────────────────────────────────────────────────────────────┐

└───────────────┬───────────────────┘  └────────────────┬────────────────┘
                └──────────────┬─────────────────────────┘

│  RabbitMQ  长任务・审计・RAG 增量索引（topic: task.# audit.# rag.#）     │
```

**设计主线**：业务领域层（catalog / OrderTools）是唯一事实源；Agent 只是消费方；
卡片取自工具返回而非模型复述；所有外部依赖通过适配器接入，**未部署时自动降级到进程内实现**，
因此离线 CI、本地演示、生产部署共用同一套业务代码。

## 二、双后端同契约

| 维度 | Python | Java |
|---|---|---|
| 框架 | LangChain 1.5.2 + LangGraph + FastAPI | LangChain4j 1.24.0 + Spring Boot 3.3.6 |
| Agent 循环 | `create_agent` → `CompiledStateGraph` | `@AiService` + `@Tool` 自动循环 |
| 会话记忆 | `InMemorySaver` + `thread_id` | `@MemoryId` + `MessageWindowChatMemory` |
| 工具 | 10 个 MCP 只读工具 + 三级降级 | `@Tool/@P` + 稳定错误码与「何时不该用」 |
| 结构化输出 | `ToolStrategy(PurchaseIntent)` | AiService 返回类型 / JSON 解析校验 |
| 流式 | `astream_events` → SSE | `StreamingChatModel` → `TokenStream` |
| 模型网关 | `infra/llm_gateway.py` | `LlmConfig` + `LlmRouter` |
| RAG | `capabilities/rag/*` | `RagService` + `langchain4j-milvus` |
| 加固 | `hardening/*` | `InjectionGuard` / `AclService` / `ReliabilityService` |
| MQ | `MessageBus`(pika/inproc) | `AgentEvents`(Spring AMQP) |
| 契约校验 | `tests/contract/check_contract.py`（40 条路径静态比对） | 同左 |

**Java 侧三个已核实的坑**（写进 `LlmConfig.java` 与 `docs/04`）：
1. 1.24.0 确实存在（2026-11-18 稳定版），BOM 为 `dev.langchain4j:langchain4j-bom:1.24.0`；
2. 1.x 把 `ChatLanguageModel` 改名成 `ChatModel`，照旧教程写直接编译失败；
3. 同类型多个 `ChatModel` bean 注入会启动失败 → 只暴露一个 `@Primary`，其余供应商放 Map
   由 `LlmRouter` 显式选择，`@AiService(wiringMode=EXPLICIT, chatModel="primaryChatModel")`。

## 三、请求主链路（SSE，Python 侧）

```
浏览器 POST /v1/chat
  → nginx /api/py/* → FastAPI
  → build_agent()（create_agent + 中间件链 + checkpointer + response_format）
  → astream_events(v2)：
      on_chat_model_stream    → SSE token
      on_tool_start/end       → SSE tool_start / tool_end
      ToolMessage             → 提取结构化卡片 → SSE cards
  → done（含 trace_id / token 用量）
```

事件序列 `meta → (tool_start → tool_end → cards)* → token* → done`，异常发 `error`。
Java 侧用 `StreamingChatModel` + `TokenStream` 输出同构 SSE 事件。

### 中间件链（LangChain 1.5 一等扩展点）
`GuardMiddleware`（注入/PII/长度） → `UserContextMiddleware`（可信 header 注入 user_id/tenant）
→ `AuditMiddleware` → `ModelRetryMiddleware` → `ModelCallLimitMiddleware` → `ToolCallLimitMiddleware`。
越靠前越外层；身份**绝不由模型自述**，来自网关注入的 `X-User-Id` / `X-Tenant-Id`。

## 四、RAG 全链路（Milvus）

```
问题 → 查询理解(改写/分解/multi-query/HyDE/不检索判定)
     → ACL 生成 Milvus expr（acl_tenant + acl_roles）【先过滤再检索】
     → 稠密向量(HNSW) + BM25 全文 → RRF 融合 → Rerank 特征重排
     → 注入防护 sanitize + wrap_as_data(trust=untrusted)
     → 带 [n] 编号的 Prompt 拼接（指令区 / 数据区物理隔离）
     → 抽取式作答 + 引用对齐 + 忠实度校验 + 无据不答
     → 缓存(精确/语义/检索/embedding) 与知识更新失效
```

**集合契约**：`chunk_id`（与内容绑定，内容不变则复用）、`doc_id/version`（增量与撤销）、
`embedding`（生产 bge-m3 / text-embedding-v3，1024 维）、`text`、`acl_tenant/acl_roles`。
索引 HNSW（M=16, efConstruction=200），检索 ef=64；标量字段下推过滤。

高阶分支：`Text2SQL`（模板生成 + SQL Guard：SELECT-only / 单语句 / 表白名单 / 自动 LIMIT）、
`Text2Cypher`（参数化模板）、`GraphRAG`（种子实体 → 多跳 BFS 子图）、`Ontology`（7 类实体 × 8 关系
domain/range 约束）。外部图库 Neo4j 走适配器契约。

## 五、Agent 编排与可靠性

### 编排
- **隐式循环**：`create_agent` 模型自主决定下一步（v1 主链路）
- **显式循环**：`planning.react_loop` / `plan_and_solve`（Thought→Action→Observation，依赖、重规划、重复动作终止）
- **状态机**：`workflow.StateGraph` 5 节点 + 条件边，写操作直接 `escalate`
- **多 Agent**：Supervisor 分派 + 商品/订单/售后 3 专家，并行执行、结构化结论交换、冲突检测
- **HITL**：事前批准 / 事中打断 / 事后审核；超时**默认拒绝**；人工结果结构化回注上下文

默认倾向 `workflow > 单 Agent > 多 Agent`（总纲 0.6），决策依据由 `decision.agent_fit()` 给出。

### 可靠性原语
| 原语 | 实现 |
|---|---|
| 重试 | `RetryPolicy` 指数退避 + jitter；**接入 `errors.classify` 做可重试分类**，422/403/quota 不重试 |
| 超时 | `with_timeout` 分层（单次/单工具/单任务/端到端） |
| 幂等 | `IdempotencyStore` sha256 key + TTL + replay；Java `ReliabilityService.idempotent` |
| 熔断 | `CircuitBreaker` closed/open/half_open |
| 降级 | `degrade_chain` 如实返回生效来源；MCP `builtin→adapters→local` |
| 终止 | `TerminationPolicy` 步数/耗时/重复动作/工具失败/用户中止 + **按金额硬终止**（`cost.LEDGER`） |
| 长任务 | `LongTaskRunner` 步骤级 checkpoint + 心跳 + 断点跳过已完成步骤 |
| 沙箱 | AST 白名单表达式级（**非 OS 隔离**）+ Code Mode 交叉校验 |

## 六、上下文、记忆与成本

- **Token 预算**：`TokenBudget` 五段预留（system/tools/history/retrieved/output）；
  KV-cache 友好布局「稳定前缀在前，易变内容在后」；抽取式压缩 + 工具结果截断 + 优先级裁剪。
- **三层记忆**：会话记忆（checkpointer / `@MemoryId`）、长期记忆（`LongTermStore` namespace/key +
  版本 + TTL）、用户记忆（`GovernedMemory`：白名单写入策略、临时语过滤、冲突留痕、30 天半衰期、可删除）。
- **成本**：`CostLedger` 每成功任务成本、`有效成本 = 单任务推理成本 / 成功率 + 人工兜底成本`、
  预算硬终止、10s 窗口异常花费检测。降本顺序固定为 **缓存 > 路由 > 精简上下文 > 换模型**。

## 七、可观测与发布

- **Trace**：`Tracer` trace/span 树（agent/model/tool/retrieval 子 span），对齐 OTel GenAI 语义；
  Java 侧 Micrometer + `InvocationContext.parentInvocationId`（1.24.0 支持嵌套调用链）。
- **Metrics**：QPS、成功率、P50/P95/P99、token 用量、工具错误率、检索命中率、按租户成本归因。
- **评测**：7 个可复算评分器 + Golden Case / Bad Case / Replay + **pass^k**（k 次全对）。
- **重放**：`replay.py` 完整轨迹落盘（含上下文快照）→ 固定外部依赖确定性重放 →
  回到第 N 步改写后重跑 → 改 prompt 前后 digest diff。
- **发布**：`PromptRegistry` 版本/hash/canary 灰度/promote/回滚；`MODEL_VERSION_PIN` 阻断上游静默升级；
  CI 三重门禁（成功率 / 成本 / P95）+ 契约一致 + 红队 block_rate + pass^k。

| 层 | 措施 |

## 十、关键设计决策

1. **双后端同契约而非两套前端**：契约文件机器可读 + CI 静态比对，避免漂移。
2. **适配器可降级**：外部服务不是「跑起来的前提」，而是「配置到位即切换」，CI 才能零依赖。
3. **事实源单一**：catalog / OrderTools 派生 MySQL seed、Milvus 语料与图谱，避免三处数字打架。
4. **外部内容一律数据化**：这是间接注入最有效的一层，且可规则判定、可回归。
5. **ACL 下推到检索前**：召回后再丢既泄漏存在性又浪费预算。
6. **训练不在本仓库**：应用侧只负责路由、成本、评测与训练任务契约。
7. **默认 workflow、克制多 Agent**：多 Agent 带来的隔离收益要大于成本/延迟/归因开销才引入。

> 边界与未验证项集中列在 `docs/07-边界与风险.md`；本沙盒只实跑了 Python 全量测试、
> 契约静态校验与 compose 配置校验，Java 编译与真实基础设施拉起需本地环境。
