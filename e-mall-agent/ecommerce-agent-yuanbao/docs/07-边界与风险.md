# 边界与风险（如实清单）

> 这份文档比「全部已实现」更有价值：能说清能力边界，比声称什么都做过更可信。

## 一、本沙盒没验证到的

| 项 | 原因 | 缓解 |
|---|---|---|
| **Java 后端编译** | 沙盒只有 JDK 11，无 javac / mvn | pom 与源码按已核实的 1.24.0 语义编写；本地 JDK17+Maven 3.8+ 执行 `mvn test` |
| **Milvus / MySQL / Redis / RabbitMQ 实际拉起** | 镜像与网络限制 | `docker compose config` 校验；四套适配器全部有进程内降级，离线测试不依赖 |
| **真实大模型调用** | 无 API Key | `LLM_MODE=mock` 全链路可跑；切 `real` 走 OpenAI 兼容网关 |
| **前端 npm build / vitest** | 依赖安装受网络限制 | 沿用 `scripts/verify-core.mjs` 零依赖校验；新增 6 个 Vue 组件做了结构校验 |

## 二、刻意不做的（判断，不是遗漏）

1. **训练执行**：SFT / LoRA / QLoRA / DPO / RLHF / 量化 / 剪枝 / 蒸馏需要 GPU、数据集、
   训练框架与独立服务。本仓库只提供 `TrainingJobSpec` 契约与数据集字段规范，
   `executed_here` 恒为 `False`。应用岗的真实职责是「会接、会路由、会算成本、会评测」。
2. **OS 级沙盒**：`harness.sandbox_eval` 是 AST 白名单表达式级（禁 import/属性/赋值/循环 +
   空 builtins），**不是**容器/gVisor/seccomp。执行不可信代码仍需外部隔离。
3. **HashEmbedding**：确定性哈希特征，用于验证「切片→向量化→召回→重排→引用」工程链路，
   不是语义向量。生产换 bge-m3 / text-embedding-v3 时保持 `embed(text)->vector` 接口即可。
4. **外部向量库/图库**：Milvus、Neo4j 给出统一适配器契约与配置；Python 侧离线用内存实现，
   生产替换实现不改 Pipeline。不把「接口已定义」说成「已接入」。
5. **A2A / 多模态 / 浏览器自动化**：标注为【拓展】，本轮只给契约与扩展点，不假装实现。
6. **写操作**：10 个 MCP 工具保持只读；退款/下单只登记意向或走审批，不真实扣款。

## 三、仍需在生产补的

- 凭据隔离：现在用环境变量，生产应接 Vault/KMS，按工具独立凭据（C#16）。
- 不可篡改审计与留存期：MySQL audit_log 是普通表，需追加 WORM/签名。
- 分布式限流与公平调度：Redis `incr` 是单键，多租户配额需更细。
- 完整确定性重放：当前固定录制 outputs，尚未冻结所有外部依赖（时钟/随机/网络）。
- 评测集规模：Golden Case 7 条 + 红队 8 条是骨架，需从线上 badcase 持续扩充（7.7）。

## 四、版本风险

langchain4j 1.x 迭代很快（3 周一个功能版），`AiServices` 构造方式、
`ContentRetriever` 返回类型、starter 自动配置项都可能变。**必须锁版本**
并读升级说明；本项目 pom 固定 1.24.0 + BOM。Python 侧固定 langchain 1.5.2 / core ≥1.8.4。

# 附二：第三轮复盘（用户追问「再复盘和检查一遍」）

> 第二轮修完 12 个问题后，第三轮把口径从「文件在不在」推进到
> **「代码真的会被执行吗、编译真的能过吗」**。结论：又查出 **6 类真问题**，
> 其中 Java 侧 **13 个编译错误**是硬伤 —— 上一轮说「未编译所以不知道」，
> 这轮把 JDK17 + Maven 环境真搭起来后，发现源码根本编译不过。

## 一、Java 侧：从「未验证」变成「验证出真错误并修好」

本轮真下载了 Temurin JDK **17.0.21.1** 与 Maven **3.9.16**，导入沙盒 CA 打通 Java TLS，
又核实了 `langchain4j-bom:1.24.0` 的完整坐标表：

- **上一轮怀疑错了**：`langchain4j-milvus / -mcp / -test / *-spring-boot-starter`
  在 `1.24.0` 直查确实 404，但 **pom 通过 BOM 管理版本**，BOM 把它们解析到
  `1.24.0-beta34`（已实测 200）。所以 pom 坐标本身是对的，不是虚标。
- 但用 **JDK17 `javac` + 真实 1.24.0 jar** 编译 main 源码，直接报 **13 个错误**：
  - `AgentEvents.java` 三处非法参数声明 `Queue longTaskQueue q)`（多了变量名）、缺 `import java.util.Map`；
  - `InjectionGuard.java` 正则 `!\[` 转义写错（illegal escape character）；
  - `ShoppingAssistant.java` 把 `@AiService` 写成 `dev.langchain4j.service.AiService`，
    1.24.0 真实包是 **`dev.langchain4j.service.spring.AiService`**（jar 内已核实）。
  - 全部修复后 **javac 0 error**，脚本 `backend-java/scripts/verify_compile.sh` 可复现。

> **仍未验证的**：`mvn compile` 完整依赖树下载超出沙盒时间盒（Spring Boot parent 会拉
> 数十个 BOM pom，网络很慢）；`mvn test`（8 个 @Test）、Spring 上下文启动、
> `@AiService` 运行时装配、两个 `ChatModel` bean 歧义、starter 与 Boot 3.3.6 的兼容性
> **全部没有跑过**。准确表述是「main 源码语法与 import 已验证」，不是「Java 后端能跑」。

## 二、适配器：上一轮说「接了 MySQL/Milvus」其实是假的

| 问题 | 真相 | 修复 |
|---|---|---|
| `RelationalStore.execute/query` | **完全没用 `self._engine`**，永远走 sqlite；`active_backend` 却可能报 mysql | 新增 `_run_remote`（`?` → `:pN` 命名参数）、`_to_named` 校验、真 `engine.begin()` 执行；`stats()` 按方言查 `information_schema`，不再谎报 |
| `MilvusAdapter` | `__init__` 不探活，`search/delete` 无异常保护 → 连不上时整个请求炸 | `list_collections()` 真探活；upsert/search/delete 三段异常回退本地，`stats` 暴露 `last_error` |
| `KVStore` | 初始化 ping 有 try，但**运行中 Redis 掉线**时 `set/get` 直接抛异常 | 调用层异常捕获 → 自动切内存后端 |
| `MessageBus` | 同上，`basic_publish` 掉线会抛 | 异常回退进程内队列；`__init__` 补 `self._ch = None`（离线时原本无此属性） |

新增 `test_infra_adapters_realpath.py` **10 例**，专测「真调用路径 + 掉线回退」，
其中 `test_relational_stats_does_not_claim_mysql_without_engine` 就是防止再次虚报后端。

## 三、前端与部署：第二轮修复自己带进来的小坑

- `ConsolePanel.vue` 模板里写了 TS 非空断言 `tabs.find(...)!.comp` —— **Vue 模板不支持 `!`**，
  会编译失败。改成 `markRaw` + `computed activeComp`。
- `App.vue` 加了按钮但**文件原本没有 `<style>` 段**，`.topbar-right` / `.console-toggle` 无样式。已补。
- OTel 把 `attributes/genai` 挂在 **metrics** pipeline，该 processor 对 metrics 的 action 支持
  随 collector 版本变化，有启动风险。改挂 traces，metrics 只保留 batch。
- RabbitMQ `definitions.json` 只挂载不加载 → 新增 `rabbitmq.conf` 配 `management.load_definitions`
  并在 compose 挂载；MinIO 旧变量换成 `MINIO_ROOT_USER/ROOT_PASSWORD`（`.env.example` 同步）。
