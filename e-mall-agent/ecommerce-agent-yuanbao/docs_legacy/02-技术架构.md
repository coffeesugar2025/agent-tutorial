# 技术架构说明书 · 小栈电商智能体

## 一、总体分层

```
┌─────────────────────────────────────────────────────────────┐
│  Vue 3 前端 (Vite)                                          │
│  App.vue 会话状态机 → api/client.ts (fetch SSE) → 组件层    │
└───────────────────────────┬─────────────────────────────────┘
                            │ POST /api/v1/chat  (SSE)
                            │ GET  /health · /v1/tools · /v1/intent
┌───────────────────────────▼─────────────────────────────────┐
│  FastAPI 接入层  app/api/routes.py                          │
│  CORS · 请求校验(Pydantic) · StreamingResponse                │
└───────────────────────────┬─────────────────────────────────┘
┌───────────────────────────▼─────────────────────────────────┐
│  Agent 运行层  app/agent/runtime.py                         │
│  agent.astream_events(..., version="v2") → SSE 事件翻译       │
│  ToolMessage → 结构化卡片提取                                 │
└───────────────────────────┬─────────────────────────────────┘
┌───────────────────────────▼─────────────────────────────────┐
│  LangChain 1.5  create_agent  (CompiledStateGraph)          │
│  model · tools · system_prompt · middleware                  │
│  checkpointer(InMemorySaver) · response_format(ToolStrategy) │
│                                                             │
│  中间件链（外 → 内）                                        │
│  PromptGuard → ToolAudit → ModelCallLimit                   │
│  → ToolCallLimit → ModelRetry                               │
└──────────┬──────────────────────────────┬───────────────────┘
           │ bind_tools / invoke           │ ToolNode 执行
┌──────────▼─────────────┐      ┌──────────▼────────────────────┐
│ 模型层                 │      │ MCP 工具层                    │
│ mock: ScriptedChatModel│      │ langchain.mcp.MCPAdapter      │
│ real: init_chat_model  │      │  ↓ list_tools()               │
└────────────────────────┘      │ FastMCP Server (stdio/HTTP)   │
                                 │  ↓ 调用                       │
                                 │ app/services/catalog.py       │
                                 │ (纯 Python 领域规则与演示数据) │
                                 └────────────────────────────────┘
```

**分层原则**：领域规则（`catalog.py`）不依赖任何 AI 框架；MCP Server 只做协议暴露；Agent 层只做编排；接入层只做协议转换。任一层可独立替换。

## 二、LangChain 1.5 能力映射

| 1.5 能力 | 本项目用法 | 代码位置 |
|---|---|---|
| `create_agent` | 构建 model→tools→model 循环，返回 LangGraph 编译图 | `agent/builder.py` |
| `langchain.mcp.MCPAdapter` | 1.4+ 内置 MCP 支持，标准 `MCPConfig`，`list_tools()` 动态发现 | `agent/mcp_tools.py`、`config.py` |
| `AgentMiddleware` | v1 一等扩展点，自定义 + 5 个内置中间件 | `agent/middleware.py` |
| `response_format` / `ToolStrategy` | 结构化意图 `PurchaseIntent`，结果在 `structured_response` | `builder.py`、`schemas.py` |
| `checkpointer` | `InMemorySaver` + `thread_id` 实现多轮记忆 | `builder.py`、`runtime.py` |
| `astream_events(v2)` | token 增量 + 工具生命周期事件 | `agent/runtime.py` |
| `init_chat_model` | `openai:gpt-4o-mini` 字符串按需加载厂商包 | `builder.py` |
| 标准内容块 | `message.content` 兼容 str 与 list[dict] 两种形态 | `runtime.py`、`mock_model.py` |

**版本要点**：LangChain 1.5（2026-11-11）要求 Python ≥ 3.11、core ≥ 1.8；1.5 新增 Decisions API 与 `ModelRouterMiddleware` / `AutoModeMiddleware`（需显式 `classifier=`）。本项目未使用 beta 决策模型，但预留了 `ModelRouterMiddleware` 的接入点（见第九节）。1.4 起 MCP 内置于 `langchain.mcp`，旧的 `langchain_mcp_adapters.MultiServerMCPClient` 通过 `MCP_CLIENT=adapters` 兼容保留。

## 四、请求时序（SSE 主链路）

```
浏览器                FastAPI              create_agent         MCP Server
  │ POST /v1/chat        │                     │                    │
  ├─────────────────────>│ astream_events(v2)  │                    │
  │                      ├────────────────────>│ model.invoke       │
  │  event: meta         │<────────────────────┤                    │
  │<─────────────────────┤                     │ AIMessage(tool_calls)
  │  event: tool_start   │<────────────────────┤                    │
  │<─────────────────────┤                     │ ToolNode → tool.ainvoke
  │                      │                     ├───────────────────>│
  │                      │                     │<───────────────────┤ JSON 结果
  │  event: tool_end     │<────────────────────┤ ToolMessage         │
  │  event: cards        │<────────────────────┤                    │
  │<─────────────────────┤                     │ 再次 model.invoke   │
  │  event: token × N    │<────────────────────┤ AIMessageChunk      │
  │<─────────────────────┤                     │                    │
  │  event: done         │<────────────────────┤ graph END           │
  │<─────────────────────┤                     │                    │
```

**SSE 协议**

| event | data | 前端处理 |
|---|---|---|
| `meta` | `thread_id, user_id, model` | 记录会话元信息 |
| `token` | `text` | 追加到回答气泡 |
| `tool_start` | `name, args, index` | 新增一条 running 工具轨迹 |
| `tool_end` | `name, summary` | 把最近同名的 running 轨迹置为 success |
| `cards` | `cards[]` | 渲染结构化卡片 |
| `error` | `message` | 展示错误，不中断后续解析 |
| `done` | `elapsed_ms, tool_calls` | 结束流式、显示统计 |

前端用 `fetch + ReadableStream` 而非 `EventSource`：因为 `EventSource` 仅支持 GET，而对话需要 POST 携带 `thread_id / user_id`。`api/sse.ts` 把「按 `\n\n` 切块 + 保留未闭合尾部 + 容错解析」做成纯函数，可独立单测。

## 五、中间件链（LangChain 1.5 一等扩展点）

组合顺序「越靠前越外层」：

| 顺序 | 中间件 | 钩子 | 作用 |
|---|---|---|---|
| 1 | `PromptGuardMiddleware`（自定义） | `wrap_model_call` | 命中注入关键词直接返回 `ModelResponse` 短路，不发起模型调用 |
| 2 | `ToolAuditMiddleware`（自定义） | `wrap_tool_call` | 强制注入 `user_id`、PII 脱敏、写审计日志、统计耗时 |
| 3 | `ModelCallLimitMiddleware` | 内置 | 单次运行模型调用上限 `2×max_calls` |
| 4 | `ToolCallLimitMiddleware` | 内置 | 单次运行工具调用上限 `max_calls` |
| 5 | `ModelRetryMiddleware` | 内置 | 模型异常重试 1 次，失败继续而非抛断 |

自定义中间件基于 `AgentMiddleware`，同步/异步钩子成对实现（`wrap_model_call` + `awrap_model_call`、`wrap_tool_call` + `awrap_tool_call`），保证 `invoke` 与 `ainvoke` 行为一致。归属注入通过 `request.override(tool_call=...)` 完成，不修改工具本身。

## 六、MCP 接入与降级

```
MCP_TRANSPORT=stdio（默认）
  MCPAdapter({"mcpServers":{"shop":{"command": sys.executable,
                                     "args":[server.py], "env": {...}}}})
  → 拉起 FastMCP 子进程 → list_tools() → 10 个 BaseTool

MCP_TRANSPORT=http
  MCPAdapter({"mcpServers":{"shop":{"url":".../mcp"}}})
  → Streamable HTTP 连接独立部署的 MCP 服务

MCP_CLIENT=adapters
  MultiServerMCPClient 兼容写法（旧项目迁移场景）

任一环节异常
  → 自动降级为 4 个本地 @tool（local_*），/health 与 /v1/tools 如实反映来源
```

**生命周期**：`MCPAdapter` 是异步上下文管理器，由 FastAPI `lifespan` 持有，而不是每请求创建——因为 Agent 调用工具期间 adapter 必须保持打开。应用关闭时 `__aexit__` 统一释放。

**命名空间**：多服务器配置下工具名自动带 `{server}_` 前缀，避免撞名；本项目单服务器保留原名。

## 七、会话记忆与状态

- `InMemorySaver` 作为 checkpointer，每次请求传 `config={"configurable":{"thread_id": ...}}`。
- 每轮 `ainvoke` 返回完整 `messages`，`run_sync` 从中提取 `ToolMessage` 生成轨迹与卡片。
- 测试通过 `agent.aget_state(config)` 断言同一 thread 的消息累积、不同 thread 互不干扰。
- 生产替换点：Postgres/Redis Checkpointer（LangGraph 接口不变），跨进程长期记忆用 `store`。

## 八、结构化输出与意图识别

```python
class PurchaseIntent(BaseModel):
    intent: Literal["search_product","order_query","price_calc",
                    "after_sale","recommend","other"]
    keywords: list[str]
    budget_max: float | None
    category: str | None
    needs_tool: bool
    confidence: float

agent = create_agent(model, tools=[],
                     response_format=ToolStrategy(PurchaseIntent))
result["structured_response"]  # 已被 Pydantic 校验
```

`ToolStrategy` 把 schema 注册为一个工具，对不支持原生结构化输出的模型也能工作；若模型支持 provider-native，直接传 schema 类即自动选择 `ProviderStrategy`。前端并行调用 `/v1/intent` 展示意图标签，失败静默降级不影响主对话。

## 九、部署、可观测与扩展点

| 关注点 | 当前实现 | 生产替换 |
|---|---|---|
| 模型 | `ScriptedChatModel` / `init_chat_model` | 接 `ModelRouterMiddleware(classifier=...)` 按意图选模型（1.5 新增） |
| MCP 传输 | stdio 子进程 | Streamable HTTP + OAuth / mTLS |
| Checkpointer | `InMemorySaver` | Postgres / Redis |
| 工具鉴权 | 中间件注入 `user_id` | 工具侧接 RBAC + 租户隔离 |
| 可观测 | `/v1/audit` 环形日志 + 可选 LangSmith；v2 `Tracer` / `MetricsRegistry` / `EvalSuite` | OpenTelemetry / LangSmith 全量 trace |
| 领域数据 | 内置演示数据 | `catalog.py` 换成 ERP / 商品中台 SDK |
| 推荐 | 规则召回 | 向量检索 / 召回重排服务 |
| 人工介入 | v2 `ApprovalStore`：写操作挂起 → approve/reject/edit → `resume`（等价 interrupt-resume 语义） | `HumanInTheLoopMiddleware`（1.4.6+ 支持 `interrupt_mode="per_call"`）+ 持久化工单 |
| 上下文压缩 | v2 `context.compress`：Token 预算 + 抽取式摘要 + 工具结果截断 + 优先级裁剪 | `SummarizationMiddleware`（1.5 支持独立 `summarizer=` 模型） |
| 长期记忆 | v2 `LongTermStore`（namespace/key + 版本 + TTL） | LangGraph `BaseStore` / Postgres / Redis |
| 模型路由 | v2 `ModelRouter` 按成本/延迟/意图/本地优先打分 | `ModelRouterMiddleware(classifier=...)` |

**安全清单**：提示词注入防护 · 用户归属强制注入 · PII 脱敏 · 工具调用次数上限 · 只读工具边界 · CORS 白名单 · 输入长度与空白校验 · 错误信息不回传内部堆栈。

## 十、关键设计决策与取舍

| 决策 | 原因 |
|---|---|
| 领域规则下沉到纯 Python 层 | 业务正确性由单测保证，不依赖模型表现；MCP 与 Agent 都只是消费方 |
| 卡片数据直接取自 `ToolMessage` | 不让模型「复述」数字，避免价格/库存被改写 |
| 提供脚本化 ChatModel | 无 Key 也能真实跑工具循环，演示与 CI 不依赖外部服务；不是跳过 Agent 的假实现 |
| `astream_events` 而非 `astream` | 同时需要 token 增量与工具生命周期事件，且能区分节点 |
| SSE 而非 WebSocket | 服务端→客户端单向流，HTTP/1.1 友好、可自动重连；取消用 AbortController 即可 |
| MCP 连接放进 lifespan | adapter 必须活到 Agent 工具调用结束；每请求建连会有子进程风暴 |
| 三级降级 | 演示环境里单点 MCP 故障不应让整个对话不可用 |
| 不用 1.5 beta 决策模型 | 保持核心链路稳定；`ModelRouterMiddleware` 作为明确扩展点预留 |
