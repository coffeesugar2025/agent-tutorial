# 20 · 岗位地图与学习路径

## 20.1 用人单位真正在看的六件事

| 能力 | 面试怎么问 | 书里对应 |
|---|---|---|
| 业务抽象 | "把这个需求拆成状态机和接口" | 05 / 06 |
| Agent 工程化 | "你的 Loop 怎么停？失败怎么恢复？" | 03 / 15 / 16 |
| RAG 与知识治理 | "版本串台怎么解决？引用怎么校验？" | 09 / 10 / 11 |
| 生产可靠性 | "幂等键怎么设计？超时设几层？" | 15 / 14 |
| 评测与迭代 | "你怎么证明这次改动有用？" | 17 |
| 垂直行业理解 | "年假口径你们怎么定的？" | 全书的 HR 场景 |

一句话：**不是"会调 API"，是"能上生产干活"。**

## 20.2 岗位分布与考察差异

| 方向 | 典型系统 | 考察重点 |
|---|---|---|
| 工业制造 | MES/ERP/PLM/SOP 问答/排产 | 系统集成（COM/RPC）、术语准确性、离线部署 |
| 医疗生命 | 病历结构化、知识图谱、辅助决策 | 引用可追溯、幻觉零容忍、合规 |
| 政务客服 | 工单派发、回访、Control Tower | 并发、成本、话术合规、多轮稳定性 |
| 企业内部效率（HR/财务/OA） | 审批流、跨系统读写、报表 | 权限、审计、HITL、幂等 |
| AI 原生产品 | 多模态、长任务生成 | 流式体验、任务恢复、成本控制 |

共同点：**接系统、调工具、读知识、跑流程、出结果、可验收。**

## 20.3 一份可写的简历句式

不要写"熟悉 LangChain / Agent / RAG"，写**你解决的具体问题 + 数字**：

> 基于 LangGraph 设计 HR 审批 Agent，落地 Offer 发放流程；用状态机 + CAS 版本控制保证并发安全，HITL 四道校验拦下自批/超时/越权；Golden Case 回归覆盖 12 条核心用例，上线后任务成功率 94%，P95 延迟 2.1s，单任务成本降到 T3 独占方案的 1/4。

这段话里的每个数字，本书都有对应的一章能让你真的做出来。

## 20.4 五周路径（按本书章节）

| 周 | 章节 | 产出（能拿给别人看的） |
|---|---|---|
| 1 | 00–04 | 一条带结构化输出的链 + 一个能选对工具、能回填错误的 Agent |
| 2 | 05–08 | 一个带重规划的 Plan-and-Execute + 一个审批状态机 + 记忆与上下文预算 |
| 3 | 09–12 | 一套"混合检索 + 版本治理 + 引用校验"的 RAG，加一个 MCP 工具服务 |
| 4 | 13–17 | 多智能体评审 + HITL offer 审批 + 可靠性五件套 + 长任务 + 评测集 |
| 5 | 18–20 | Vue3 前端工作台 + 成本测算表 + 简历与作品集 |

**每周都要留一个"可运行的仓库"**，比读完 21 章更有用。

## 20.5 三个作品建议（面试最有效）

1. **一个 RAG（有版本治理 + 引用校验）**：证明你不是"接了个向量库"。
2. **一个带 HITL 的流程 Agent（审批/发信/写库）**：证明你懂"不可逆动作"。
3. **一套评测集 + 一份 bad case 迭代记录**：证明你会迭代，这是最稀缺的。

## 20.6 常见误区

| 误区 | 现实 |
|---|---|
| "把 demo 跑通就能面试" | 面试问的是"如果并发两个审批人怎么办" |
| "模型越强越好" | 成本与延迟是硬约束，分档才是常态 |
| "Prompt 万能" | 该定死的地方必须写进代码（第 06 章） |
| "多智能体更先进" | 单 Agent + 门禁能解决 80% 的场景（第 13 章） |
| "评测是上线后的事" | 没有评测，你连"变好了"都说不出来（第 17 章） |

## 20.7 继续深入的方向

- **LangGraph 深水区**：subgraph、`Command` 路由、持久化后端（Postgres saver）、时间旅行（`get_state_history`）。
- **RAG 深水区**：增量索引、chunk 级版本 diff、cross-encoder 重排、query 改写与多跳。
- **观测深水区**：OpenTelemetry 打通、Token 级成本归因、线上 A/B。
- **安全**：Prompt 注入防御、工具权限最小化、输出脱敏、审计留存。

## 20.8 结课自检

- [ ] 我能独立画出"一个 Agent 的完整状态图"（含终止条件与失败分支）
- [ ] 我能说清"哪些交给模型、哪些必须由代码保证"
- [ ] 我能为一个 RAG 设计切片、元数据、版本、引用四件事
- [ ] 我能为一个写操作设计幂等键、超时、降级、熔断
- [ ] 我能用 Golden Case 证明一次改动有效

五条都能答，你已经具备"上生产干活"的底子，剩下的只是项目经验。

## 20.9 最后一句

这本书里所有 demo 都用了真的 LangChain / LangGraph 原语，没有一句"伪代码"。
你现在缺的不是知识，是**把一个场景做到能验收**。挑一个你公司真实存在的流程，按第 05/06/14/15/17 章的顺序做一遍，那就是你的项目经验。
