# 00 · 导读与环境准备

## 0.1 这本书不假设你会什么

只假设三件事：会用命令行（Windows 上是 PowerShell，知道 `cd` 切目录）、写过一个 `for` 循环、不抗拒看报错。

**不假设**你会机器学习、Transformer、向量数据库、前端框架、Docker。

## 0.2 全书的技术底座：LangChain + LangGraph

这不是一本"手写 Agent 原理"的书，也不是"只讲概念、代码是伪代码"的书。

**每一章的 demo 都用真实的 LangChain / LangGraph 原语实现**，你可以直接把这套写法搬进公司的项目：

| 要做的事 | 用的原语 | 出处 |
|---|---|---|
| 调模型 | `ChatOpenAI` / `init_chat_model` | `langchain-openai` |
| 拼提示词、串流程 | `ChatPromptTemplate`、LCEL（`prompt \| model \| parser`） | `langchain-core` |
| 结构化输出 | `with_structured_output(PydanticModel)` | `langchain-core` |
| 工具 | `@tool`、`StructuredTool`、`args_schema` | `langchain-core` |
| Agent 循环 | `create_agent`、`ToolNode`、`tools_condition` | `langchain`、`langgraph` |
| 手搭图 / 状态机 / 多智能体 | `StateGraph`、条件边、`Send` | `langgraph` |
| 断点、HITL、长任务 | `InMemorySaver` / `SqliteSaver`、`interrupt()`、`Command(resume=...)` | `langgraph` |
| Memory | `RunnableWithMessageHistory`、`InMemoryVectorStore` | `langchain-core` |
| RAG | `RecursiveCharacterTextSplitter`、`BM25Retriever`、`EnsembleRetriever` | `langchain-text-splitters`、`langchain-classic` |
| 观测 | `BaseCallbackHandler`、`astream_events(version="v2")` | `langchain-core` |

两个必须提前知道的事实（本书实测，`langchain 1.5.0` / `langchain-core 1.8.0`）：

1. **1.x 和 0.x 差别很大**。`EnsembleRetriever` 搬到了 `langchain-classic`；`InMemoryVectorStore` 的 `filter` 参数收的是**函数**不是 dict；同步的 `stream_events` 已不支持 v2，必须用 `astream_events`。这些坑书里都标出来了。
2. **没有 API Key 也能跑完整套**。`demos/common/llm.py` 里的 `ScriptedChatModel` 是 LangChain 官方假模型的子类，能返回带 `tool_calls` 的消息，所以 `create_agent` 的工具循环、结构化输出解析、事件流全都是真实发生的，只是"模型"是剧本。

## 0.3 环境安装

### Python 3.12

```powershell
python --version    # 3.12.x（3.13 也实测通过）
```

推荐用 `uv` 管版本（比 conda 轻）：

```powershell
pip install uv
uv python install 3.12
```

### 一次性装齐依赖

```powershell
cd HR-Agent-教程\demos
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`requirements.txt` 里这些都是**必装**，不是可选：

```
langchain==1.5.0
langchain-core==1.8.0
langgraph
langchain-openai
langchain-community
langchain-classic
langchain-text-splitters
pydantic>=2.7
rank_bm25
sqlalchemy
```

### 可选（章节里会说明什么时候需要）

`langchain-mcp-adapters` + `mcp`（第 12 章接真 MCP 服务）、`langchain-neo4j`（第 11 章真图谱）、`langsmith`（第 17 章接托管 Trace）。

## 0.4 接真模型（可选）

复制 `demos/.env.example` 为 `demos/.env`：

```
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-你的
```

任何 OpenAI 兼容服务都行：DeepSeek、通义、智谱、vLLM、Ollama、Xinference。
没填 Key 时每个 demo 第一条输出会提示"已切换到 ScriptedChatModel"，这不是报错。

## 0.7 先纠正三个误解

**一、Agent ≠ 会调 API 的聊天机器人。** 聊天机器人是"进一段话、出一段话"；Agent 多了两件事：能改变外部世界（调工具、写库、发邮件）、能自己决定下一步。所以一半工作量不在模型上。

**二、效果不好多半不是模型不够强。** 是上下文喂错了、工具描述写糊了、该走流程的地方让模型自由发挥、失败了没有重试降级。同一模型，改工程结构，成功率能从 40% 到 90%。

**三、HR 场景"简单"是错觉。** HR 是高敏感 + 强流程 + 多系统的典型：薪酬身份证病历绩效泄露一次就是事故；offer 背调入职离职每一步都有审批时限；ATS、考勤、薪酬、OA、IM 五套系统。这三条正好是 Agent 工程最难的部位。
