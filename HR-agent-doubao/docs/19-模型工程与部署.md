## 19.2 换厂商：四行代码

```python
from langchain.chat_models import init_chat_model

m = init_chat_model("deepseek-chat", model_provider="deepseek", base_url=..., api_key=...)
m = init_chat_model("gpt-4o-mini",   model_provider="openai")

```

**统一接口的价值**：你的 20 个 demo、5 个工具、3 个图，全都只依赖 `BaseChatModel`。换厂商零改动——这是"用框架"最实际的收益之一。

## 19.3 三档模型

| 档 | 典型 | 单价（每千次） | 延迟 | 用来做什么 |
|---|---|---|---|---|
| T1 | 小模型 / 本地 7B | 3.0 元 | 0.8s | 分类、抽取、改写、意图识别 |
| T2 | 中档 | 30 元 | 1.5s | 常规问答、工具调度、简单归纳 |
| T3 | 旗舰 | 114 元 | 4.0s | 复杂推理、多步规划、对外文案、审计结论 |

## 19.4 路由：规则优先，模型兜底

```python
def route(task: str, budget_left: float) -> str:
    # ① 红线条目永远不降档
    if task in RED_LINE:            return "T3"     # 仲裁 / 合规结论 / 对外 offer 文案
    # ② 明确的简单任务，直接给最便宜的
    if task in CHEAP:               return "T1"     # 意图分类 / 字段抽取 / 摘要
    # ③ 预算紧，降一档
    if budget_left < 0.2 and task in NORMAL: return "T1"
    return "T2"
```

★ **预算紧张可以降档，但红线不能降。** 把"合规结论"降给 T1，省下的钱不够赔一次事故。

## 19.5 成本测算（这是本章最该记住的表）

```
  每年 100 万次任务：全用 T3 → 416,100 元；全用 T1 → 11,096 元
  真实分布：60% T1 + 30% T2 + 10% T3 → 110,960 元
  ★ 分档的本质：把 90% 的简单任务赶到便宜档，成本直接降到 1/4
```

算法很简单：

```python
cost = Σ (tasks_n × share × unit_price) / 1000
```

但**先要估计任务分布**——这才是难点。做法：上线前跑一周，统计每类任务的量与 token。

## 19.6 四个调优旋钮

| 旋钮 | 影响 | 建议 |
|---|---|---|
| temperature | 稳定性 vs 多样性 | 抽取/分类 0；文案 0.6–0.8 |
| max_tokens | 成本上限 vs 截断风险 | 按任务定，别用默认最大值 |
| top_p | 采样范围 | 通常不动，改 temperature 就够 |
| 结构化输出 | 稳定性 | 能用就用，别靠正则抠文本 |

## 19.7 什么时候该微调

一个判断顺序（**别一上来就 SFT**）：

```
① prompt 写好了吗？五部位写全了吗？      ── 没 → 先改 prompt（第 02 章）
② 有评测集吗？能证明改 prompt 没用吗？    ── 没 → 先建 Golden（第 17 章）
③ 是"知识不会"还是"格式不对"？            ── 知识 → RAG（第 09-11 章）
④ 格式/风格/术语总不对，且数据有 500+ 条标注 → LoRA
⑤ 要改模型"行为习惯"，且有偏好对数据      → DPO
⑥ 都不行、且要极致性能                   → 全量 SFT（很少见）
```

实测一节对比（同题三档）：

```
  T1：说'年假按公司规定执行'，不给天数  ← 会闯祸
  T2：'满 1 年 5 天，满 3 年 7 天'        ← 够用
  T3：'…依据《员工手册》第十四条，满 1 年不满 5 年 7 天；
      试用期内按转正后折算，需 HRBP 确认'  ← 敢上审计
```

差别不在"知识"，在**引用与边界意识**。这也说明：**该用贵的地方只有一处——对外、可追责的输出。**

## 19.8 本地部署

| 方案 | 适用 | 代价 |
|---|---|---|
| Ollama | 单机开发、内网 | 吞吐低，适合 1–3 人用 |
| vLLM | 生产推理（Linux + CUDA） | 需 GPU；吞吐高，PagedAttention |
| SGLang | 高并发 + 结构化输出 | 同上，生态稍新 |
| Xinference | 多模型统一管理 | 功能全，但重 |

内网/隐私场景（薪酬数据、员工身份证）**必须本地或专有云**。

## 19.9 常见坑

1. **全用旗舰模型**：成本是分档的 4 倍，效果只高一点点。
2. **把红线任务降档**：省小钱赔大事。
3. **以为换模型能解决 prompt 问题**：换三次模型不如改一次五部位 prompt。
4. **没有 baseline 就上 LoRA**：不知道 LoRA 前后差多少，等于赌博。
5. **`init_chat_model` 的 `model_provider` 名字写错**：报"unknown provider"，去查官方 provider 列表。
6. **vLLM 直接暴露在公网**：没有鉴权的推理端点，一天就被刷爆。
