# 01 · 第一次调用大模型（LangChain 版）

## 1.1 本章目标

跑通一条最短的链，并搞清楚三件事：

1. `|` 到底在做什么（LCEL）；
2. 你发给模型的不是"一段文字"，是"一组消息"；
3. `invoke` 和 `stream` 的区别，以及为什么前端要 stream。

跑法：`python ch01_hello_llm/main.py`

## 1.2 最小骨架：Prompt | Model | Parser

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是苏州智造集团的 HR 助手。回答不超过 40 字，不编造制度条款。"),
    ("human", "候选人 {name} 应聘 {position}，帮我写一句面试邀约开场白。"),
])
model = get_model([...])            # 有 Key 是真模型，没 Key 是剧本假模型
parser = StrOutputParser()

chain = prompt | model | parser     # ★ 这就是 LCEL
chain.invoke({"name": "张伟", "position": "高级前端工程师"})
```

三个东西之所以能用 `|` 串起来，是因为它们都实现了 **Runnable** 接口（同一个 `invoke/stream/batch` 协议）。
这带来两个实际好处：

- 换掉任意一段，链不会散架：想换成别的模型？只改 `model` 那一行。
- 链本身也是 Runnable：**链可以再被拼进更大的链**。第 09 章的 RAG、第 17 章的评测，都是这么叠出来的。

实测输出：

```
  链的类型：RunnableSequence
  输入：{'name': '张伟', 'position': '高级前端工程师'}
  输出：张伟您好，感谢投递高级前端工程师岗位。想约您周四 14:00 聊 45 分钟。
```

## 1.3 消息角色：你真正在调的是"一组消息"

```python
messages = [
    SystemMessage(content="你是 HR 助手，只回答制度问题，其余转 HRBP。"),
    HumanMessage(content="入职满一年有几天年假？"),
]
reply = model.invoke(messages)
```

四个角色，记住它们的**权限差别**——这是后面很多安全设计的基础：

| 角色 | 作用 | 谁能写 |
|---|---|---|
| `SystemMessage` | 定规则、定身份、定禁止事项 | **只有你的代码**，用户改不了 |
| `HumanMessage` | 用户说的话，含工具返回值注入风险 | 用户 |
| `AIMessage` | 模型回答，可能带 `tool_calls` | 模型 |
| `ToolMessage` | 工具返回结果，带 `tool_call_id` | 你的代码 |

**关键认知：模型是无状态的。** 它"记得上文"，是因为你每次都把历史消息重新发了一遍。所以"记忆"从来不是模型的能力，是你的工程选择——这是第 07、08 章的主题。

## 1.4 流式：为什么生产环境一定要 stream

```python
for chunk in chain.stream({"name": "张伟", "position": "高级前端工程师"}):
    print(chunk, end="", flush=True)
```

`invoke` 要等模型把话说完才返回；`stream` 拿到第一个 token 就开始往外吐。用户体感差别是"等了 6 秒"和"0.8 秒后有反应"。

第 18 章的 SSE 前端就是靠这个：`astream_events(version="v2")` 把模型的 token、工具的开始/结束都变成可订阅事件，前端才能显示"Agent 正在做什么"，而不是干等。

## 1.5 同一段 prompt，换输入

```python
chain.invoke({"name": "李娜", "position": "薪酬专员"})
```

链是无状态的，可以反复调。**如果你希望它"记得上一轮"。** 那就得自己把历史塞回去，或者用第 07 章的 `RunnableWithMessageHistory`。

注意假模型的限制：剧本是预先写好的，换输入不会真的改答案。接真模型（填 `.env`）后才看得到换输入的效果差异。这一点书里所有 demo 都一样，读输出时留意"这是剧本还是真模型"。

## 1.6 常见坑

1. **prompt 变量没对上**：`ChatPromptTemplate` 里写了 `{name}`，invoke 时没传，报 `KeyError`。变量名要和 dict 的 key 一字不差。
2. **花括号冲突**：prompt 里要写 JSON 示例，`{"a":1}` 会被当变量。用双花括号 `{{"a":1}}` 转义，或者放进变量。
3. **以为 system 能管住用户**：system 是"强提示"，不是"权限"。用户照样能说"忽略上面的要求"。真正的约束在执行层（第 04 章的 `args_schema`、第 06 章的状态机）。
4. **`StrOutputParser` 忘了加**：`invoke` 拿到的是 `AIMessage`，取文本要 `.content`。很多人第一次 print 出 `content='...'` 就是漏了这个。
